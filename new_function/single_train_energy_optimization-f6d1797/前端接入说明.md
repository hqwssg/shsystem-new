# 前端接入说明（给编码代理阅读）

> 本文件是**机读优先**的接入契约说明。每条结论都给出了可执行路径或可查字段，
> 不要靠猜测补全。机器可读版本见 `api_contract.json`。

## 1. 这是什么

- 包名：`single_train_energy_recovery`
- Python 包：`regenerative_braking`
- 作用：单列车再生制动能量回收：RHONN 状态辨识 + EKF/UKF 在线更新 + NSMC 控制
- 输入：四类物理参数 JSON + 一条制动工况剖面（速度/坡度时间序列）
- 输出：逐拍时序表（CSV）+ 单场景能量台账与指标（JSON）+ 中文统计报告（Markdown/SVG）
- 语言：**机读键名保持英文，说明层为中文**。不要翻译或改写任何 CSV/JSON 键名。

## 2. 三步跑通

```bash
python -m pip install -r requirements.txt
python examples/demo_call.py
```

`examples/demo_call.py` 会跑平直制动场景（`s1_flat_braking`，8 s / 80 000 拍），
打印中文摘要、写出 CSV，并对物理门禁做断言。它以**退出码 0** 表示链路正常。

## 3. 调用入口

| 函数 | 用途 |
| --- | --- |
| `load_component_bundle` | 读取四类参数，装配列车/电机/变流器/储能对象 |
| `build_simulator` | 构造仿真器实例（每次运行前显式复位被控对象） |
| `build_closed_loop_controller` | 装配主算法联合闭环控制器 |
| `run_case` | 跑单个场景 × 单个控制器，返回 SimulationResult |
| `build_validation_scenarios` | 构造验证场景剖面；传 shared 才含真实线路族 R |
| `baseline_catalog` | 列出全部可对比控制器 |

完整签名（照抄即可，参数名与默认值以代码为准）：

```text
load_component_bundle(paths: 'Optional[ProjectPaths]' = None) -> 'ComponentBundle'
build_simulator(bundle: 'ComponentBundle') -> 'RegenerativeBrakingSimulator'
build_closed_loop_controller(*, limits: 'Optional[DutyLimits]' = None, rhonn_config: 'Optional[RHONNConfig]' = None, identifier: 'Optional[OnlineIdentifier]' = None, nsmc_config: 'Optional[NSMCConfig]' = None, converter_params: 'Optional[DCConverterParameters]' = None, storage_params: 'Optional[object]' = None, sample_time_s: 'Optional[float]' = None, apply_control_channel_gain_prior: 'bool' = True, measurement_filter_time_constant_s: 'float' = 0.0, measurement_filter_alpha: 'float' = 1.0, storage_resistance_time_constant_s: 'float' = 0.0, history_limit: 'int' = 2000, reference_strategy: 'str' = 'storage_matched', feedback_resistance_upper_factor: 'Optional[float]' = None, controller_profile: 'str' = 'custom') -> 'ClosedLoopController'
run_case(bundle: 'ComponentBundle', series: 'ProfileSeries', case: 'BaselineCase', config: 'Optional[SimulationConfig]' = None) -> 'SimulationResult'
build_validation_scenarios(bundle: 'ComponentBundle', dt: 'float', *, shared: 'Optional[SharedRailwayData]' = None, config: 'Optional[ScenarioProfileConfig]' = None) -> 'Tuple[ValidationScenario, ...]'
baseline_catalog(controller_profile: 'str' = 'default', *, reference_strategy: 'str' = 'storage_matched', reference_upper_factor: 'Optional[float]' = None) -> 'Tuple[ValidationBaseline, ...]'
```

典型调用顺序（**必须按此顺序**，参考量装配依赖前一步的对象）：

```python
from regenerative_braking.io.data_paths import load_project_paths
from regenerative_braking.simulation.scenario_runner import load_component_bundle, build_simulator
from regenerative_braking.simulation.closed_loop import build_closed_loop_controller
from regenerative_braking.validation.scenarios import build_validation_scenarios
from regenerative_braking.simulation.regenerative_simulator import SimulationConfig

paths = load_project_paths()                 # 读 configs/data_paths.yaml
bundle = load_component_bundle(paths)        # 四类参数 -> 物理对象
scenario = build_validation_scenarios(bundle, 1e-4)[0]  # 只要族 1–9 时可省 shared
controller = build_closed_loop_controller(   # 主算法
    converter_params=bundle.converter_params,
    storage_params=bundle.storage_params,
    sample_time_s=1e-4,
)
result = build_simulator(bundle).run(
    scenario.series,
    controller=controller,
    config=SimulationConfig(dt=1e-4, record_stride=10),
)
ledger = result.ledger.to_dict(kwh=True)     # 能量台账，键名统一 _kWh 后缀
metrics = result.to_scenario_metrics().to_flat_dict()  # 指标
```

## 3.1 场景必须知道的一件事

`build_validation_scenarios` 不传 `shared` 只有 **13** 档；
传入共享线路数据才得到完整 **14** 档（多出族 R 真实线路区段制动）。

```python
from regenerative_braking.io.data_loader import load_shared_railway_data
shared = load_shared_railway_data(paths)
scenarios = build_validation_scenarios(bundle, 1e-4, shared=shared)   # 14 档
```

场景清单（含变体）直接读 `api_contract.json` 的 `scenarios`，每条有 `id / variant / family / steps`。

## 3.2 控制器不能跨场景复用（会算错）

主算法 `rhonn_nsmc` 的 `reset()` **保留在线学到的权重**（热启动）。所以：

```python
# 正确：每个 (场景, 控制器) 新建一次
for scenario in scenarios:
    controller = build_closed_loop_controller(
        converter_params=bundle.converter_params,
        storage_params=bundle.storage_params,
        sample_time_s=1e-4,
    )
    result = build_simulator(bundle).run(scenario.series, controller=controller, config=config)

# 错误：控制器建在循环外 —— 第二个场景读数是热启动的，依赖运行顺序
```

实测影响：同一场景同一控制器重跑，净存入 `1.023138811709 → 1.022264756990 kWh`（长剖面约 0.085%）；
几秒级小剖面可直接翻到 0（热启动后 `u_eq` 落到充电门槛以下，整段不充电）。
复用发生时，结果的 `extra_notes` 会带「⚠ 控制器实例第 N 次运行」标注——可以拿它做自检。

## 4. 输入参数

四个 JSON 共 **64** 个数值字段，全部带中文溯源。前端若要暴露参数编辑界面，
直接从 `api_contract.json` 的 `input_parameters[].fields` 渲染，不要手抄。

| 文件 | 字段数 | 说明 |
| --- | --- | --- |
| `data/single_train/train_parameters.json` | 19 | 列车与制动工况参数（2 万吨 C80 重车代表工况） |
| `data/single_train/motor_parameters.json` | 13 | 牵引电机再生特性（包络、效率与过压降额） |
| `data/single_train/dc_dc_parameters.json` | 20 | 双向 DC-DC 变换器（T1/T2 双开关平均模型） |
| `data/single_train/storage_parameters.json` | 12 | 储能系统（飞轮 45 kWh + 钛酸锂 100 kWh 聚合模型） |

**其中 36 / 64 个字段是虚拟值**（甲方资料未到位，取工程合理值保证链路可跑，未经实测确认）。分布：`assumed` 19、`placeholder` 17。逐字段清单见包内 `docs/virtual_data_register_2026-11-05.md`。

界面要求：

- 每个参数字段**必须原样显示 `data_status`**（契约里 `input_parameters[].fields[].data_status`）；
- `placeholder` / `assumed` 的字段可以编辑、可以展示，但**不得**标成工程值或对外承诺；
- 若业务方拿正式资料替换，改完 JSON 三处（数值 / `field_data_status` / `provenance`）后需要重跑标定，能量与电压峰值都会变。

字段条目结构：

```json
{"field": "input_voltage_window.min_v", "value": 1200.0, "unit": "V",
 "cn": "母线电压窗口下限",
 "provenance": "母线电压窗口 1200 / 1500 / 1800 V：...",
 "provenance_scope": "group:input_voltage_window", "data_status": "placeholder"}
```

- 上屏一律用 `provenance`；`provenance_raw` 是同一字段的溯源原话，仅供审计比对，不要上屏。
- `provenance_scope` 为 `self` 表示该字段有独立出处；为 `group:<键>` 表示与同组字段共用一条说明。
- `unit` 可能为空串，表示无量纲或该字段为结构化取值；**不要自行补单位**。
- `data_status` 是参数溯源等级，界面上应原样呈现（`official/real/derived/assumed/placeholder`）。
- 改参数只改 JSON 数值，**不要改字段名**；字段名被代码直接读取。

## 6. 口径纪律（会直接导致数据看错）

- `machine_keys_are_english`：CSV/JSON 键名保持英文；中文只出现在说明层，不得改写键名
- `energy_units`：能量统一 kWh；功率统一 W（时序 CSV）或 kW（摘要，见字段后缀）
- `same_side_comparison`：跟踪指标参考取储能侧可吸收功率，不取轮端再生功率
- `regen_caliber`：问「回收了多少再生」必须用 storage_net_of_grid_import_energy_kWh（= 净存入 − 电网回吸）；storage_energy_kWh 与 captured_energy_kWh 含从母线回吸的电网电，只能当端口吸收量，直接当回收量会把电网电算成再生
- `closure_tolerance`：能量闭合相对残差 < 1e-4 为通过

补充三条必须遵守的：

1. **能量数字必须带步长**。`dt = 1e-4` 与 `dt = 2e-4` 的读数不同，混算即错。
2. **不要跨控制器比较不同侧的量**。跟踪误差的参考是储能侧可吸收功率，不是轮端再生功率。
3. **`ledger.loss_energy_kWh` 含回网能量**，不是发热耗散；它已是旧口径，新界面改用 `storage_net_of_grid_import_energy_kWh`（净再生）表示「回收了多少」。
4. **「净」字只能用在 `storage_net_of_grid_import_energy_kWh` 上**。`storage_energy_kWh` / `captured_energy_kWh` 含从母线回吸的电网电（实测 s1 上差 0.0313 kWh，约 0.8%），把它们标成「净存入 / 净回收」会把电网电算成再生；`regenerative_efficiency` 与 `capture_ratio` 已按扣回吸后的口径计算。

## 7. 错误处理

| 异常 | 触发条件 | 前端应做什么 |
| --- | --- | --- |
| `DataPathError` | `configs/data_paths.yaml` 缺失，或共享数据未就位 | 检查 `data/shared/` 是否完整 |
| `ProfileError` | 剖面不可达（减速度或速度越界） | 提示用户改工况，不要静默改小 |
| `ConverterNumericalError` | 电压越出 3 倍窗口 | 视为数值发散，停止本次仿真 |
| `ClosedLoopError` | 参考量装配参数只给一半 | 补齐 `converter_params` 与 `storage_params` |

所有异常都是显式抛错，**没有静默降级路径**。捕获后应原样展示 message，不要吞掉。

## 8. 性能参考

| 项 | 读数 | 条件 |
| --- | --- | --- |
| 主算法单场景 | 约 37–41 s / 80 000 拍 | `s1`，`dt = 1e-4`，单线程 |
| 无控制基线单场景 | 约 2 s / 80 000 拍 | 同场景，占空比恒 0 |
| 内存 | 单场景数组约 80 MB | `record_stride = 10` |

前端不要在主线程同步等 40 s，用后台任务 + 进度轮询。

## 9. 不要做的事

- 不要改 `regenerative_braking/` 内任何计算代码（控制链是定型口径）；
- 不要为省时间把 `dt` 调大后再声称能量结论（步长改变读数）；
- 不要复制 `FIELD_GLOSSARY` 到前端代码（必须引用，不能拷贝）；
- 不要把 `data_status` 为 `placeholder` 的参数当成工程值展示给最终用户。
