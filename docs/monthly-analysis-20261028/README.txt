月度能耗统计分析接入说明（2026-10-28）

本次范围
能耗统计分析统一读取 emission_collection_node_data_month。新增模型后端查询接口，更新主前端统计页面。复用既有公司/模板/节点/物理采集点权限、月度表和 POI/ECharts；没有新增业务表或前端依赖。
碳排放报告及大屏的既有接口继续保留。本次没有执行线上部署，也不需要重导已有核算任务。

用户操作
1. 打开“能耗统计分析”，在左侧选择分公司。页面自动带出当前可访问的有效基准模板；没有基准时必须手动选择模板。
2. 模板决定采集点范围；可以跨年查询。选择月、完整自然季度或完整自然年。月模式支持任意连续整月。
3. 选择能源品类、能耗场景（一级/二级）、部门或站点。按核算点统计时，选择公司、模板及核算点，包含它与下级有效采集点。
4. 数据口径默认为核算采用值，可切换原始值或修正值。已有结果时，切换口径自动重新查询；其他筛选改变会清除旧结果，点击查询加载新结果。
5. 各公司数据对比允许每家公司独立选择模板。也可在单家公司内选择多个部门或站点进行组织对比。
6. 同比逐期对齐去年；月/季/年环比分别对齐上月、上季、上年。连续多月的环比逐月对齐上月。
7. 查看修正明细可查看两套数值、采用值、差额、采用方式及质量说明；同比/环比可查看基期明细。
8. Excel 按当前条件和口径导出，包含统计分组、本期修正明细、期间合计、口径说明；同期比较另有基期明细。

数据规则
采用值逐条按 total_emission_calc_method 选择：1=修正，2=原始。能耗、排放成套选择，不回退另一套字段，不重新计算排放或核对因子。
data_status=2 不计为真实零值。字段缺失保留空值；全缺失合计为空；有部分有效值时展示有效部分并标记不完整。真实零值显示0。补全/估算/异常只提示，不拦截统计。
能耗按能源品类+单位分别统计；排放沿用月度表保存的标准 tCO2e 结果。不同能耗单位不直接相加，没有新增单位换算。
模板只界定采集点范围，月度表是物理采集点当前最新记录；重新生成月度结果后统计随表更新。它不是某个历史核算任务的冻结快照。
同一汇总内按“采集点类型+ID+年月”去重。同一物理点跨公司模板重叠时，总卡片及期间合计去重，各公司行分别展示，并显示重叠提示。
归属与分类以月度记录为准，归属空值进入“未明确归属”。没有月度行时展示“未生成月度结果”，不直接认定原始采集缺失。

整合部署
1. 先核对目标分支已经具备月度表实体/建表脚本，以及当前 CompanyOwnershipService、CollectionScopeService、NodeInclusionResolver 和基准模板能力。
2. 阅读接口说明，结合 code.patch 或 source/ 中的增量文件合并。主前端与模型后端配套更新。不要直接覆盖整套项目或环境配置。
3. 构建模型后端 tpfhs-9/backend（Java17，mvn test/package）和主前端 ruoyi-ui（npm run build:prod）。本轮没有修改模型前端。
4. 模型后端实际路由 /api/monthly-analysis/*；主前端使用 /carbon-api/monthly-analysis/*，由已有代理映射到 /api。不要重复添加 /api。
5. 保留目标环境数据库、端口、登录、安全和文件配置。接口使用 carbon:analysis:view，不要求模型编辑权限。
6. 核对月度表已存在。缺表时报部署缺项，不回退旧任务总量。
7. 本地演示脚本仅用于本地库，不是上线必执行项。正式环境应该查询真实月度结果。
