# 重空协调数据初始化

本文件夹保存朔黄重空协调的完整原始示例数据。项目构建时会读取这里的 28 个文件，生成自包含迁移 `sql/carbon-energy/V5__shuohuang_full_dataset.sql`；服务器更新脚本会自动导入。创建和执行任务仍依赖仓库内的 `energy_recovery_agent` 与其 Python 依赖。

导入后能量页能打开：

- 项目：`shuohuang_demo`（朔黄演示）
- 版本：`v1`（第1版）
- 状态：`planning_placeholder`（规划占位）

`data/` 里是该版本的 28 个原文件，路径与库中一致，包含车站、区间、列车、运行图、供电臂、储能、扰动和联合参数。这些数是规划占位，不能当成正式工程结论。正式线路请另发数据版本，不要改这一版的文件后再当正式数据用。

## 生成迁移

在仓库根目录执行：

```powershell
python tools/zhongkong/generate_dataset_sql.py
```

生成器只使用 Python 标准库，并校验文件、站点、区间、供电臂、列车和运行图数量。`tools/server-update/build-update.ps1` 与 `docker/copy.sh` 会自动执行生成器，通常无需手工运行。

本地数据库已经执行过 `V1__energy_tables.sql` 后，可导入：

```powershell
mysql -uroot -p carbon_emissions < sql/carbon-energy/V5__shuohuang_full_dataset.sql
```

迁移只允许升级旧占位摘要或重复导入相同摘要。目标库存在同名但内容不同的 `shuohuang_demo / v1` 时会直接失败，不会覆盖该版本。

## 导入后核对

1. 用管理员登录，打开重空协同与能量优化，能看到「朔黄演示 / 第1版」。
2. 版本状态为规划占位，并包含 28 个文件、33 个站点、1390 个区间、76 个供电臂、2 种列车参数和 2 个储能设备。
3. 运行图包含 2 列列车、22 条站次；新建任务后，任务结果必须由 Python 引擎实际计算并写入。
4. 用一个非管理员账号登录：未绑定其部门时看不到该项目；绑定后再登录则能打开。
