两个算法模块演示数据初始化
生成日期：2026-11-10

用途
为“重空协同与能量优化”和“单列车能量回收”创建可选择的演示数据版本，解决只更新代码、数据库旧版本仍缺少规划配置或机车曲线的问题。
本包依据本地已验证输入生成，自包含数据；不依赖本机路径、原始算法压缩包、Python或项目源码。
先部署“算法新版11-9整合补丁_20261109.zip”对应代码及实际Python运行目录，再初始化本包数据。
本包不是碳排放报告公司设备/图片初始化包；两个包可分别使用。

初始化后选择哪个版本
新增独立项目：算法演示·2026-11新版（非正式）
项目编码：algorithm_demo_20261110

重空协同：
1. 新版常规任务演示（2026-11-10），版本编码demo_general_20261110。
   用于运行图审查、运行图优化、重空方案评价、滚动重调度、联合参数稳健性。
   包含新版编组/机车曲线、运行图及联合参数区间等37个冻结文件。
2. 储能选址定容演示（2026-11-10），版本编码demo_planning_20261110。
   用于储能选址与定容。含17个冻结文件及完整候选站点、技术、关联、场景和规划策略。
   策略synthetic_cost_robust_v1，场景集synthetic_typical_days_v1。
   这是本地验证用的简化合成规划算例，只有1个候选站点/技术/场景，含为测试设置的价格参数，不能用于投资判断。
   演示时可先使用粗搜索、每维2档、结算步长300秒。

单列车：
新版单列车回收演示（2026-11-10），版本编码demo_single_20261110。
用于主算法仿真、控制器对比和多场景验证，包含机车曲线、完整编组及四类专用参数。
数据来自11月9日本地页面已通过的版本；关联来源指向本包新建的常规重空版本。

储能规划务必选第2个重空版本。第1个常规版本不带规划合同，切换它做储能规划仍会提示缺项，这是两个测试版本用途不同。
旧“朔黄演示/第1版”等版本保持原样，不会被本包补写或覆盖。

最简单的执行方式
1. 将init_algorithm_demo.sh上传到服务器，例如：
   /opt/algorithm-demo-init/init_algorithm_demo.sh
   这一个文件已内嵌全部SQL和数据；可以只上传它。
2. 找到数据库容器名称：
   docker ps --format '{{.Names}} {{.Image}}'
3. 执行（ruoyi-db替换为实际数据库容器名）：
   ALGORITHM_DEMO_DB_PASSWORD='1275410782h' bash /opt/algorithm-demo-init/init_algorithm_demo.sh --container ruoyi-db --database carbon_emissions --user root --account admin
4. 此命令使用已提供的数据库密码，不需要交互输入。密码会出现在shell历史记录及短暂的进程环境中。--user是MySQL账号，--account是网站登录账号，两者含义不同。
5. 必须看到ALGORITHM_DEMO_INIT_OK和Completed。记录输出的登录账号、实际部门ID及备份目录。
6. 刷新页面，使用--account指定的网站账号登录两个算法模块，在版本下拉框选择上面三个新版本。
   不会自动创建计算任务或填入已有计算结果，需要用户自己提交新任务测试。

账号与可见范围
默认--account admin，脚本从目标sys_user解析该账号的实际dept_id，再核对有效sys_dept。
不会使用本地301/3000等部门ID，不创建账号/部门/角色或菜单权限。
项目绑定给这个账号所在部门；同部门且具有模块权限的账号也可见。
如果要给另一部门使用，可使用该部门已有登录账号再次执行--account；数据不会重复创建，只添加该部门的项目绑定。
账号不存在、被禁用、没有部门或部门无效时停止。账号本身需已有两个算法模块的访问权限，本包不扩大角色权限。

非Docker数据库
宿主机已有MySQL 8.x的mysql/mysqldump客户端时：
   bash init_algorithm_demo.sh --local --host 127.0.0.1 --port 3306 --database carbon_emissions --user root --account admin
可增加--backup-dir /私有备份目录。建议用数据库管理员账号执行，不将数据库密码写入命令行。

前置条件
MySQL 8.x，两个模块现有表/字段已部署，目标表为InnoDB，系统已有有效登录账号与部门。
数据库账号需读取sys_user/sys_dept，读写清单内18张表，以及CREATE TEMPORARY TABLES、CREATE/ALTER ROUTINE、EXECUTE权限。
脚本只创建临时种子表与执行后删除的辅助过程，不新建业务表，不修改现有表结构。
SQL含完整数据，辅助过程约4.4MB。服务端max_allowed_packet建议16M或更大；Shell脚本会先检查，过小会停止并提示。
目标数据库容器内需能调用mysql和mysqldump；宿主机需Bash和Docker工具。无需Python、pip或项目目录。
不要使用mysql --force忽略错误，不要将容器名写成没有数据库客户端的Web容器。

重复执行与保护行为
新增项目、两个重空版本、一个单列车版本和限定的部门绑定，数据条数见data-manifest.json。
重复执行相同内容不重复添加、不重置创建时间。
已有相同演示项目/版本的数据被手工改变时，返回EXISTING_DATA_DIFFERS并保留原数据，不直接覆盖。
其他项目的唯一键冲突会停止，事务内本次新增数据全部回滚。
已有禁用的该项目部门绑定会返回BINDING_DISABLED，不擅自重新启用。
不会导入旧任务、结果、日志，不覆盖原有项目或版本，不重新计算历史数据。

执行检查
SQL方式核对：在同一数据库执行verify_algorithm_demo.sql（只读）。
应看到2个已发布重空版本、1个已发布单列车版本，单列车has_curves=1，以及对应部门的两个enabled=1绑定。
规划站点、技术、场景、策略各1条；总冻结文件54条。完整预期条数及固定ID见data-manifest.json。
页面：储能规划版能带出策略和场景集；单列车新建任务能选到新版本，不再因曲线缺失被过滤。
如果页面没有变化，先刷新，再核对当前登录账号实际部门、项目绑定及主服务/算法是否连接同一数据库。
数据完整性通过不等于所有方案物理合格；保持基线、不建设、压力场景不可行或控制器越限均可能是正常算法结论。
完整曲线计算会占用时间和磁盘，先用主算法单场景验证，再做九控制器/多场景。

文件说明
init_algorithm_demo.sh：推荐入口，自带数据与按固定ID限定范围的执行前备份。
init_algorithm_demo.sql：同一份初始化SQL，供审阅或数据库人员手工执行。与Shell二选一，不需要都执行。
verify_algorithm_demo.sql：只读查询。
rollback_visibility.sql：可逆地隐藏本次演示项目，仅针对指定部门，不删除任何数据。
data-manifest.json/scope.json：项目、版本、数据条数与写入范围。
validation.json/验证记录.txt：本地隔离数据库验证证据。
CHECK_PACKAGE.py/SHA256SUMS：完整性校验，服务器可用sha256sum -c SHA256SUMS；有Python也可执行python CHECK_PACKAGE.py。

手工SQL方式
使用新连接选择目标数据库，先备份清单范围，再执行：
   SET @algorithm_seed_account='admin';
   SOURCE /绝对路径/init_algorithm_demo.sql;
建议使用mysql --max-allowed-packet=256M --default-character-set=utf8mb4的客户端。
手工SQL不自动生成备份，不应在已有未提交事务的连接里执行。

回退与备份
Shell入口在宿主机创建私有备份目录，备份仅含本次固定项目/版本及绑定范围，不是整库备份。
本次没有覆盖旧业务数据。需要暂时撤销展示时，先在rollback_visibility.sql设置初始化输出的实际部门ID，再执行，两个绑定被禁用，版本和已生成任务/结果仍保留。
需要恢复展示时，对同一项目和同一部门明确将enabled恢复为1；初始化脚本不会自动覆盖禁用状态。
不要按公司、模糊名称或整张表批量删除。备份不是可直接覆盖运行的一键回退脚本；如果执行后已有新任务或人工修改，应先核对再恢复。
账号/结构校验失败或事务异常时，不会把部分版本提交；发生成功后网络断开则先查询核对，再决定是否重跑。
