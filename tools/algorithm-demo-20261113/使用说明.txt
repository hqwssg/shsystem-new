两个算法模块：全任务统一测试数据（2026-11-13）

用途
给11月12日新算法准备一套完整的可选测试数据。只新增专用演示项目、冻结输入、关系投影、配套单列车参数及指定部门绑定。
不修改表结构，不覆盖原版本，不导入旧任务、计算结果或日志，不重新核算业务数据。
先部署“算法新版11-12整合补丁_20261113.zip”，再初始化本包。
本包是完整数据初始化包，不依赖上次数据包或本地已有数据库；目标系统的表和有效登录账号/部门需要已存在。

初始化后如何选
新增项目：算法全任务演示·2026-11-13（非正式）
项目编码：algorithm_demo_20261113_all
重空协同只选同一个版本：全任务统一演示版（2026-11-13，非正式）
版本编码：demo_all_20261113
用于运行图审查、运行图优化、重空调度、滚动重调度（含历史回放）、联合参数稳健性、储能选址与定容规划。

单列车选：全任务配套单列车版（2026-11-13，非正式）
版本编码：demo_single_20261113
用于主算法仿真、控制器对比、多场景验证和新增节能驾驶。
两个模块各有自己的版本记录，所以会有一条重空版本和一条单列车版本；它们属于同一套来源明确的配套数据。
不用再按重空任务类型来回切换“常规版/规划版/回放版”。

新增和修正内容
重空冻结输入43个，包括运行图、列车编组/机车曲线、作业约束、参数区间、规划五文件及容量匹配的历史回放。
规划包含候选点、技术、站点技术关联、场景和策略；加运行图就是页面维护的完整六张表。
规划策略synthetic_cost_robust_v1，场景集synthetic_typical_days_v1；候选点绑定当前实际数据里的供电臂，避免旧示例VPA-F-002与当前供电臂不匹配。
历史回放初始总电量72.5 kWh（两个区段各36.25），当前模型容量145 kWh，不再沿用5000 kWh旧电量。
单列车包含完整牵引力、制动力和Davis阻力字段，以及冻结编组、机车曲线和四类电气参数，支持节能驾驶。
源文件元数据中的数据库密码已移除，本包没有本地数据库凭据。

推荐执行方式（只上传一个sh也能初始化）
1. 把init_algorithm_demo.sh上传到服务器，例如/opt/algorithm-demo-20261113/init_algorithm_demo.sh。
2. 查看数据库容器名：docker ps --format '{{.Names}} {{.Image}}'
3. 执行（ruoyi-db替换成数据库容器名，不是Web容器）：
   bash /opt/algorithm-demo-20261113/init_algorithm_demo.sh --container ruoyi-db --database carbon_emissions --user root --account admin
4. 按提示输入数据库密码。--user是MySQL账号；--account是希望在网页看到数据的网站账号。
   示例中的库名carbon_emissions和数据库账号root也请替换为现场实际值。
5. 看到ALGORITHM_DEMO_INIT_OK和Completed才算成功；保留输出的实际部门ID及备份目录。
6. 刷新页面，用该网站账号选择本包新版本，创建新任务。

非Docker数据库
宿主机已有MySQL8客户端和mysqldump时：
   bash init_algorithm_demo.sh --local --host 127.0.0.1 --port 3306 --database carbon_emissions --user root --account admin
可选--backup-dir /私有备份目录。脚本会按本包固定ID范围备份；密码不放命令行，临时凭据执行结束后清除。
SQL文件也可在MySQL客户端已选好目标库后手工执行，但这不包含Shell的执行前备份；两种方式二选一。
需要改网站账号时，执行SQL前可先SET @algorithm_seed_account='实际网站账号';，然后source初始化SQL。
不要使用mysql --force忽略错误。

账号、重复执行及保护
从目标库sys_user查询--account的实际dept_id，再核对sys_dept；没有写死本地301、3000或测试73001等ID。
同部门且已有模块权限的账号可见，不创建账号/部门/角色或扩大菜单权限。
同一个账号重复执行不重复添加，也不重置已插入数据；给另一个现有部门的账号执行，仅新增该部门对演示项目的绑定。
如果本包相同项目/版本的数据已被人工更改，返回EXISTING_DATA_DIFFERS并保留现有内容，不强行覆盖。
禁用的既有绑定返回BINDING_DISABLED，不自动启用；唯一键冲突会回滚本次事务插入。

数据库前置条件
MySQL8，现有energy/single相关表均为InnoDB，客户端能够使用mysql和mysqldump。
本包涉及16张现有表（详见scope.json），只有新增数据；临时种子表和临时辅助存储过程用于校验及事务保护，不是新增业务表。
账号需要对应表读写、CREATE TEMPORARY TABLES、CREATE/ALTER ROUTINE及EXECUTE权限。
初始化SQL约3.7MB，服务端max_allowed_packet建议至少16MB；过小应先由数据库管理员调整后执行。
服务器不需要Python或pip，也不依赖项目源码；有Python时可额外运行CHECK_PACKAGE.py，或用sha256sum -c SHA256SUMS。

验证与结果边界
执行verify_algorithm_demo.sql只读检查：应有1条已发布重空版本、1条已发布单列车版本，冻结文件43个，规划站点/技术/场景/策略各1条，账号部门两个模块绑定均enabled=1。
网页储能规划应能自动带出策略/场景集，单列车节能驾驶不再因缺少牵引/制动/阻力字段而不能提交。
参考“推荐测试参数.json”和“验证记录.txt”逐项测试。不会预先生成虚假成功任务或产出文件，任务需实际执行。
支持全部任务是指输入齐备并可执行计算，不等于任意参数、所有控制器或候选方案都物理可行。保持约束标记，不以不合格基准生成节能结论。
节能驾驶仍限短区段、1e-4秒电气步长、每方案200万步；目标时间上限195秒。默认40秒区段中经验方案可能时分超限，任务仍可完成并给出原因。
储能规划是小规模合成测试，含为验证设置的成本，不用于投资判断。正式业务请使用经过确认的现场参数。
“分设备当前状态”需要用户填写当前状态，不能随意套用2500 kWh等旧数值；所填电量仍应匹配当前版本容量。

回退与文件
rollback_visibility.sql仅按指定部门隐藏本次新演示项目，可逆，不删除版本、任务或结果。
init_algorithm_demo.sh：推荐的一文件入口，内嵌全部SQL与数据。
init_algorithm_demo.sql：相同初始化SQL，供审阅/手工执行。
data/：可审阅的完整重空输入，SQL已内嵌，不必再手动上传这些文件。
data-manifest.json/scope.json：固定ID、文件哈希、条数和写入范围。
validation.json/task-validation.json/验证记录.txt：隔离初始化与实际算法验证记录。
推荐测试参数.json：各任务类型的明确验收参数。
CHECK_PACKAGE.py/SHA256SUMS：只读包校验。
