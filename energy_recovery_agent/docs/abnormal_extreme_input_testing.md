# 异常与极端输入测试

更新时间：2026-09-09

## 1. 完成范围

本专项覆盖输入从平台或文件进入算法，经过参数校验、核心计算、实时滚动、结果形成前的主要异常路径。统一入口为：

```powershell
python run_project.py test-abnormal-extreme-inputs
```

默认运行3个固定随机种子和4800个随机差分案例，输出到 `paper/experiments/abnormal_extreme_input_current/`。

## 2. 六层测试

| 测试层 | 数量 | 覆盖内容 |
| --- | ---: | --- |
| 静态数据异常 | 29 | 缺文件、坏JSON、缺列、线路拓扑、车辆、储能、资源与跨表引用 |
| 平台任务参数 | 49 | 五类任务的对象结构、白名单、整数/有限数、枚举、快照路径和设备状态 |
| 实时状态异常 | 40 | 缺字段、乱序、重复、时钟漂移、断流、设备状态、恢复与人工升级 |
| 核心极端场景 | 10 | 空功率序列、无再生、零容量、满SOC、零效率、不可用供电臂、精确限值、极大/极小有限量、多设备隔离 |
| 随机独立差分 | 4800 | 能量桶、时间切片、资源重叠和Pareto前沿 |
| 深层合同专项 | 6 | 核心构造器、导入、供电臂、资源区间、历史扰动和数据库适配器 |

正式总套件可枚举 `4934` 个案例或专项。只有六层全部通过时，总状态才是 `PASS`。

## 3. 本轮补强

平台任务参数现在会在入队前拒绝：

- 参数根节点不是JSON对象；
- 白名单外字段、非法枚举、布尔值冒充数值；
- NaN、正负无穷、负数、正数要求下的零值；
- 列车数量、种群、代数、时间和随机种子等整数参数中的小数；
- 绝对路径、`..`目录穿越、非字符串路径和超过500字符的路径；
- 空、重复或超过128字符的储能设备ID，以及非法SOC、功率和可用状态；
- 历史扰动回放与独立设备运行状态同时提交。

这些规则落实的是已经冻结的“参数白名单、非负整数秒和冻结快照内逻辑路径”合同，没有增加缺乏工程依据的列车数量或搜索规模上限。

## 4. 输出

| 文件/目录 | 用途 |
| --- | --- |
| `ABNORMAL_EXTREME_INPUT_TEST_REPORT.md` | 六层范围、数量、状态和详细结果入口 |
| `abnormal_extreme_input_summary.json` | 机器可读总门禁、组件状态和随机案例指纹 |
| `static_data/` | 静态数据异常逐案例结果 |
| `platform_parameters/` | 平台任务参数逐案例结果 |
| `realtime_state/` | 实时异常和恢复逐案例结果 |
| `core_extremes/` | 核心极端场景、分辨率和复现结果 |
| `random_differential/` | 随机案例与独立参考实现差分结果 |
| `component_logs/` | 六个深层专项的标准输出和错误输出 |

## 5. 判定边界

本专项证明当前实现能对已枚举的异常输入确定性拒绝，并在已测试极端有限值下保持数值有限、能量守恒和设备隔离。它不证明工程占位参数真实，也不替代目标数据库容量压测、生产网络断连、中间件消息风暴、操作系统资源耗尽和现场设备故障联调。

正式数据到位后仍需增加与甲方字段、单位、枚举、业务主键和实际统计分布对应的异常案例；这属于正式数据验收扩展，不影响当前通用异常测试完成状态。
