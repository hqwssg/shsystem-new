# 项目摘要：给不想通读全部文档的读者

## 一句话说明

这是一个面向朔黄铁路的重车/空车协同调度与再生制动能量回收算法原型：它模拟列车运行和功率，结算再生能量，并尝试调整运行图，使更多能量进入储能并在后续牵引需求中使用，同时不违反当前配置的运输和电气约束。

## 项目已经能做什么

- 模拟单列车的运行、牵引、制动和再生能量；
- 按时间桶、供电臂、方向和储能区段结算能量；
- 计算储能充电、已有 SOC 放电、电网补足和弃能；
- 检查容量、充放电功率、SOC、供电臂、闭塞、区间、站场和追踪间隔约束；
- 生成和评价重车/空车运行图候选；
- 输出基线、优化候选、Pareto 结果、能量账本和解释报告；
- 通过数据来源标记和结果审计区分可验证结果与规划假设。

## 当前算法边界

当前算法只负责两件事：

1. 再生制动能量回收能力分析；
2. 重车/空车调度与运行图优化。

不包含车载控制、实时控制指令下发、监控硬件、信号联锁现场认证、碳排放平台、储能设备选型和投资决策。

## 当前能量口径

默认场景是 `storage_no_direct`：

```text
再生能量不能在同一时刻直接发送给另一列牵引列车；
再生能量只能在允许的储能区段进入储能；
储能中已有的能量可以向牵引负荷放电；
同一时间桶中新充入的能量不能立即再次放电；
无法被吸收的部分计为弃能。
```

## 当前项目处于什么阶段

程序和算法已经可以运行，测试和审计体系也已建立；但输入数据仍是“部分真实资料 + 规划/虚拟/启发式参数”的混合数据。因此当前结果可以用于：

- 验证流程和代码逻辑；
- 检查约束处理；
- 比较不同候选方案的相对差异；
- 做参数区间和鲁棒性分析。

当前结果不能直接用于：

- 发布正式节能率；
- 确定储能容量和设备数量；
- 计算正式投资收益；
- 证明现场运行方案已经可执行。

## 目前最需要等待什么

需要正式确认的主要数据包括：车辆牵引/制动/Davis 参数、正式运行图、供电臂牵引和再生吸收能力、储能容量/功率/效率/成本、闭塞分区、站场和区间资源、初始车流库存及电表方向和站区间映射。

## 当前结论

项目不是“没有算法”，也不是“已经完成现场工程验证”。准确定位是：

> 算法原型和验证框架已经基本形成，目前适合进入正式数据接入、标定和现场对比阶段。
