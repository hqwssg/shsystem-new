# 扰动恢复第四阶段：多轮恢复验证

更新时间：2026-09-08

## 1. 阶段目标

第四阶段要求重新执行连续多轮滚动测试，并证明强扰动轮本身或其后的恢复轮能够重新达到核心稳健可行。验收不能靠减弱扰动或放宽约束，还必须保持已执行发车锁定、SOC连续、服务提交和完整场景评价。

## 2. 定位并修复的问题

第三阶段后的旧E15结果在第3、4轮出现锁定列车冲突。复核发现这不是新的线路冲突，而是滚动状态提交口径错误：

- 优化评价在正常场景中已经叠加本轮观测晚点；
- 执行清单却提交未叠加晚点的名义计划时刻；
- 下一轮把未经该场景验证的名义时刻锁定，形成伪造的历史冲突；
- 执行时间片能量结算同样使用名义运行图，与状态观测不一致。

当前 `RollingOptimizationResult` 明确区分：

- `schedule`：优化器选择的名义计划运行图；
- `execution_schedule`：叠加本轮正常场景已观测晚点后的实际执行运行图。

核心稳健可行时，可执行发车、下一轮锁定集合和执行期能量结算使用 `execution_schedule`。后续生产提交门禁增加 `committed_execution_schedule`；不可行时只保留已发生/锁定列车并扣留新增发车。计划运行图仍用于记录优化基准和候选解释。

## 3. 自动验收门禁

E15 schema 当前已升级为 `1.5`，并独立核验提交门禁、安全状态机及以下门禁：

1. 实际运行图与本轮重车、空车观测晚点一致；
2. 本轮实际可执行发车完整进入下一轮锁定集合；
3. 锁定历史单调增加且不被改写；
4. 执行时间片终点SOC连续传给下一轮并保持物理边界；
5. 最强扰动轮或其后至少一轮恢复核心稳健可行；
6. 每个可行轮保持可执行服务；不可行轮扣留新增决策，SOC只结算已提交运行图，资源、信号、电气和车流连续性约束不放宽。
