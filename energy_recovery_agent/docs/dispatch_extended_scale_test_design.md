# 重空协同调度第六阶段扩展规模测试设计

更新时间：2026-09-05

## 1. 目的

第六阶段第一部分先验证10列车，然后为12、16列车建立两套不能混用的实验口径：

- 固定时域口径：保持 `14400 s`（4小时）预测窗口，通过压缩发车间隔放入更多运输任务，评价任务密度、资源可行域和计算性能的共同压力。
- 扩展时域口径：保持重空 `3300 s` 发车间隔和 `840 s` 相位，按服务数量扩大预测窗口，尽量隔离列车数量对软件计算量的影响。

固定时域结果可以回答“4小时内能否安排更多任务”，但不能作为纯计算复杂度曲线；扩展时域结果可以用于经验计算规模比较，但不能称为线路运输容量。

## 2. 10列车实测

使用与第三阶段相同的当前规划/占位数据、4×1搜索、`seed=11` 和480秒门槛，测试5重+5空共10列车。基线重车间隔 `3300 s`、空车间隔 `2700 s`、空车相位 `2600 s`，最后一列重车和空车分别在 `13200 s`、`13400 s` 发车，服务数量没有被时域截断。

| 指标 | 结果 |
| --- | ---: |
| 端到端耗时 | 288.310889 s |
| 峰值进程树内存 | 129.988 MB |
| 运行是否完成 | 是 |
| 候选数 | 22 |
| 实际稳健评价数 | 24 |
| 核心稳健可行候选 | 0 |
| 返回方式 | 标称回退 |
| 选中方案约束违反量 | 0.123502 |

正常、重车晚点120秒和空车晚点120秒场景均存在咽喉进路冲突。可行性修复检查143个模板，其中130个因候选无法在4小时窗口内保持5重+5空服务而被拒绝，剩余模板也没有资源稳健可行种子。

因此当前结论是：软件可以在480秒内完成10列车快速搜索，但当前固定时域和候选域下未找到核心稳健可行解。不能把“未找到”写成10列车理论不可行，也不能把标称方案作为可执行方案。

完整证据位于 `paper/experiments/dispatch_capacity_phase6_10trains/`。

## 3. 12/16列车统一矩阵

所有案例先使用4×1预算、`seed=11`、单线程、`10 s` 结算步长和5个既有扰动场景。必须记录预测窗口内实际重空服务数，若少于请求数则案例无效。

| 案例 | 口径 | 重+空 | 时域/s | 重/空间隔/s | 相位/s | 最后重车/s | 最后空车/s | 主要解释 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| F12 | 固定时域 | 6+6 | 14400 | 2400/2400 | 840 | 12000 | 12840 | 4小时任务密度和资源压力 |
| F16 | 固定时域 | 8+8 | 14400 | 1800/1800 | 840 | 12600 | 13440 | 更高任务密度和资源压力 |
| E12 | 扩展时域 | 6+6 | 18000 | 3300/3300 | 840 | 16500 | 17340 | 近似隔离12列车计算规模 |
| E16 | 扩展时域 | 8+8 | 25200 | 3300/3300 | 840 | 23100 | 23940 | 近似隔离16列车计算规模 |

时域边界使用“发车时刻小于等于预测窗口终点”的现有契约。扩展时域额外保留至少600秒发车余量，并取整到整小时或半小时，避免最后一列恰好压线。

## 6. 验收与停止规则

每个案例按以下顺序判断：

1. `return_code=0`、未超时且生成有效 `summary.json`；
2. 基线和优化方案在预测窗口内均包含请求的重空服务数；
3. 报告耗时、峰值内存、实际稳健评价数、缓存命中数和语义 SHA-256；
4. 分开报告标称可行性和三个核心场景的稳健可行性；
5. 核心稳健可行必须满足约束违反量为0且不使用标称回退；
6. 至少在快速档成功后，才考虑增加搜索预算和随机种子；
7. 固定时域与扩展时域分别作图，不合并拟合。

## 7. 是否进入第五阶段

当前10列车耗时为288.31秒，只占480秒门槛约60.1%，内存没有异常增长；未找到稳健解的直接原因是咽喉冲突和固定时域可行域收缩，而不是命令超时。因此现在不进入第五阶段。

满足以下任一条件后才启动增量评价和并行计算设计：

- 扩展时域12列车快速档超过其720秒门槛或无法完成；
- 扩展时域16列车快速档超过其1200秒门槛或无法完成；
- 成功案例端到端耗时超过对应门槛的80%，导致更大搜索预算无法开展；
- 新剖析证明候选间未变化列车的重复评价占总耗时主要部分，并可建立严格等价测试。

固定时域案例找不到稳健解本身不触发第五阶段。它首先触发可行域诊断、运输任务密度检查以及正式咽喉/闭塞数据复核。

## 8. 12列车首轮实测结果

2026-09-05 已按冻结的4×1预算、`seed=11`、单线程和5个扰动场景串行完成 F12、E12。两项均保留6重+6空全部服务，未超时，结果如下。

| 指标 | F12 固定时域 | E12 扩展时域 |
| --- | ---: | ---: |
| 时域 | 14400 s | 18000 s |
| 端到端耗时 | 392.659111 s | 346.977897 s |
| 720秒门限占比 | 54.5% | 48.2% |
| 峰值进程树内存 | 146.098 MB | 140.430 MB |
| 候选数/实际稳健评价数 | 17/19 | 16/18 |
| 核心稳健可行候选 | 0 | 0 |
| 返回方式 | 标称回退 | 标称回退 |
| 基线→候选资源冲突数 | 6→1 | 2→5 |
| 基线→候选约束违反量 | 0.127169→0.039026 | 0.197572→0.076983 |

F12 候选相对基线的电网购电量和弃能分别下降 `2.838%`、`2.973%`，但总成本上升 `0.533%`；E12 候选的电网购电量和总成本分别下降 `2.129%`、`1.190%`，弃能与回收率没有改善。由于两项候选都存在阻塞级咽喉进路冲突，这些能源变化只能作为搜索诊断，不能作为可实施优化收益。

本轮最大耗时只占门限54.5%，内存未异常增长，因此没有触发第五阶段增量评价或并行架构优化。扩展时域没有自动恢复稳健可行性，说明问题不能简单归因于4小时时域；下一项更有价值的工作是诊断12列车资源可行域及修复模板覆盖范围。完整结果位于 `paper/experiments/dispatch_extended_scale_F12_E12/`。

## 11. 16列车快速档结果

2026-09-06 按本文件冻结口径完成E16和F16。E16/F16分别用时 `256.626418/258.270180 s`，占1200秒门限 `21.4%/21.5%`；峰值内存为 `158.062/150.008 MB`，均保留8重+8空全部服务并正常生成有效结果。

两例均没有核心稳健可行候选并返回标称回退。E16基线/返回方案资源冲突为 `4→8`、约束违反度为 `0.395145→0.133694`；F16为 `16→7`、`0.197209→0.059609`。这些返回方案不可执行，能源变化仅用于诊断。

当前计算完成的已测试上限推进到16列车，核心稳健可行的已测试上限仍为12列车。E16和F16均不触发第7节性能条件；本阶段后续已完成16列车资源可行域诊断，当前边界见 `docs/dispatch_f16_density_boundary_diagnosis.md`。

## 12. E16资源可行域定向诊断结果

单变量矩阵证明默认修复的600秒单车上限和束宽6并非瓶颈。仅采用30秒步长或仅延长到16轮仍无种子；二者联合后在第15轮、评价962个模板时找到1个资源可行种子。该种子的最大单车调整为180秒，三个核心场景资源冲突均为0，完整评价的约束、信号、电气和终端SOC违反量均为0。

因此E16当前不是结构性无解，而是默认60秒/8轮定向修复遗漏窄累计路径。第二级修复已实现并完成完整E16/F16验证，不扩大NSGA-II预算，也不进入并行架构优化。详见 `docs/dispatch_e16_feasibility_diagnosis.md`。

## 13. F16精确资源可行性复核

第11至第12节记录精确层接入前的启发式结果。2026-09-07新增精确资源可行性层后，F16在相同8重+8空、14400秒时域及三个核心扰动场景下于23.229秒找到整数秒方案，完整资源检查器确认三个场景均为0冲突、0重叠违反且流连续。因此F16应归类为启发式漏解，不能再称为当前资源模型下的不可行边界。

当前规划/占位模型下，资源可行性的已验证规模达到16列车。后续端到端接入复验还确认：精确运行图与5种虚拟储能预设组合均通过三个核心场景完整评价，最终方案的信号、电气、资源、流连续性、SOC物理边界和服务数量门禁通过。终端SOC仍有软偏差，两个±300秒非核心压力场景仍失败，因此仍不是正式线路容量或全扰动工程可行性结论。方法和证据见 `docs/exact_resource_feasibility.md`。

## 14. F16偏移质量优化结果

精确层进一步采用词典序质量目标，并直接以相位840秒的原运行图为参照，证明最大单车偏移最小值为367秒，在该边界内取得总绝对偏移3000秒的最优解。相较原纯可行解，两个指标分别改善90.855%和91.169%。质量解端到端耗时482.445秒，5个候选全部通过核心稳健评价，三个核心场景终端SOC偏差均为0。证据见 `paper/experiments/dispatch_exact_resource_f16_quality/F16_EXACT_QUALITY_REPORT.md`。
