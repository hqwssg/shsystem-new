# 代码质量专项

## 1. 目的

本专项建立一个不依赖额外开发工具安装的、可在干净环境重复执行的代码质量门禁。它关注代码结构和高风险业务路径，不把正式数据正确性、现场性能或甲方平台联调混同为代码质量结论。

## 2. 检查范围

入口为 `tools/code_quality_gate.py`，默认检查工作区源码，排除 `deliverables/`、`outputs/` 和 Python 缓存。检查包括：

- 全部纳入源码的 Python 文件能否被解析；
- 函数数量、类型标注率和函数文档字符串率；
- 复杂度超过 25 的函数，作为人工复核清单；
- 裸 `except` 与 `TODO/FIXME`，作为人工复核清单；
- 能量结算、滚动提交门禁、储能运行状态和稳健性合同四条关键业务回归。

语法错误和关键回归失败是硬门禁。裸 `except`、TODO/FIXME 和复杂度指标不自动判失败，因为项目中存在有意的兼容性/清理兜底逻辑，必须结合上下文判断。

## 3. 运行方式

完整专项：

```powershell
python tools/code_quality_gate.py --output-dir outputs/code_quality_gate
```

只运行静态检查（适合 CI 快速结构验证）：

```powershell
python tools/code_quality_gate.py --skip-critical-tests --output-dir outputs/code_quality_gate_static
```

专项已纳入 `python tools/run_ci_checks.py`。报告包括 `code_quality_summary.json` 和 `CODE_QUALITY_REPORT.md`，关键测试的标准输出与错误输出也会单独保存。

## 4. 当前边界

当前环境未安装 `ruff`、`mypy`、`pyright`、`coverage` 等第三方开发工具，因此本专项不虚构它们的结果。后续若项目统一指定工具版本，可将其作为补充门禁，但不能替代当前的语法、结构和关键路径检查。

本专项不能证明：类型在所有运行路径上正确、第三方依赖无漏洞、正式参数准确、正式节能率可信、目标服务器满足 SLA，或平台联调已经完成。当前工作区另行使用固定版本 Ruff 进行明确缺陷检查、固定版本 Pyright 对核心模块进行类型检查；这两项属于补充检查，不改变本专项的硬门禁边界。
