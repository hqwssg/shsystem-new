# E16资源可行域定向诊断

更新时间：2026-09-06

## 1. 诊断目标

16列车快速档中，E16在256.63秒内完成且服务数量完整，但常规搜索、全局修复和默认局部修复均未找到核心稳健可行候选。本轮保持8重+8空、25200秒时域、3300秒重空间隔、原资源约束和三个核心扰动场景不变，只对局部修复的步长、调整上限、迭代深度和束宽做单变量诊断。

## 2. 默认修复的最后阻塞链

使用完整E16记录中的4个最佳全局模板复现默认60秒步长、600秒上限、8轮、束宽6结果：共评价926个模板，无资源可行种子；最佳评分为 `(1, 5, 270.786913, 1080)`。

正常和空车轻微晚点场景已可行，只剩重车轻微晚点场景阻塞。5个冲突集中在：

- 蠡县咽喉：`E005/H003`、`E006/H004`、`E008/H006`，每组重叠84.302秒；
- 灵寿咽喉：`H001/E001`、`H002/E002`，每组重叠8.941秒。

因此最后障碍不是全线随机散布冲突，而是少数列车在两个咽喉的累计错峰路径没有被默认修复深度覆盖。

## 4. 找到的资源可行种子

- 重车逐列车调整：`[150, 150, 60, 60, 0, 0, 0, 0] s`；
- 空车逐列车调整：`[90, 90, 90, 0, -90, -90, -180, -180] s`；
- 最大单列车调整仅180秒，说明原600秒上限充足；
- 第15轮找到，三个核心场景的资源冲突数和重叠时间均为0；
- 服务数量保持8重+8空，列车顺序未改变。

对该种子执行现有五场景完整评价后，核心稳健结果为可行：约束违反度0、资源冲突0、信号违反0、电气违反0、终端SOC缺口0。两个±300秒强扰动诊断场景仍不可行，但按既定场景角色不参与核心稳健门禁，不能表述为“五个场景全部可行”。

## 5. 诊断结论与第二级修复实现

E16在当前规划/占位资源模型下不是结构性无解，原结果属于定向修复搜索分辨率和路径深度不足。没有证据支持扩大单列车调整上限、扩大束宽或直接扩大NSGA-II预算。

已实现第二级修复：仅当重车数与空车数之和达到16列车及以上，且常规资源修复未找到种子时，才追加30秒步长、最多16轮、束宽6的局部束搜索；单列车最大调整仍为600秒，12列车及以下继续使用60秒步长、最多8轮。找到的种子仍按现有流程执行完整稳健能量、电气、信号、服务数量和SOC评价。

完整验证结果：E16在 `paper/experiments/dispatch_extended_scale_phase10_level2/` 中找到5个核心稳健可行候选，资源冲突从4降为0，约束违反度从0.395145降为0，服务完整，未使用名义回退；搜索诊断明确记录 `repair_level=level_2_16_plus`、30秒步长和16轮迭代。F16在 `paper/experiments/dispatch_phase10_level2_f16/` 中正确触发第二级修复并在401.57秒内完成，但固定时域高密度场景仍未找到核心稳健可行候选，说明第二级修复扩大了搜索能力而不是放宽可行性约束。

本段F16结论仅代表当时的启发式搜索结果。2026-09-07精确资源可行性层已在相同F16定义域内找到并通过完整资源检查的方案，证明原结果是启发式漏解；最新结论见 `docs/exact_resource_feasibility.md`。

12列车回归验证见 `paper/experiments/dispatch_phase10_level2_regression/`：E12、F12均保持 `level_1_under_16`，仍使用60秒步长和8轮，结果有效、服务完整、核心稳健可行且约束违反度为0。

机器可读汇总见 `paper/experiments/dispatch_e16_feasibility_diagnosis/diagnosis_summary.json`，各对照的完整场景冲突链位于同目录各子文件夹的 `targeted_probe_summary.json`。
