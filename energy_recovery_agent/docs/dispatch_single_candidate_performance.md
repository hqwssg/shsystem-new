# 重空协同调度单候选性能剖析与等价优化

更新时间：2026-09-05

## 1. 目标与口径

本阶段只分析一个固定运行图候选的完整稳健评价，不把数据读取、基础轨迹仿真、储能上下文构建、候选搜索和结果写盘计入候选耗时。这样可以直接回答：搜索器每增加一个候选，主要计算成本来自哪里。

专用入口为：

```powershell
python run_project.py profile-dispatch-candidate
```

默认案例为4重+4空共8列车，重/空间隔均为 `3300 s`，有效空车相位为 `840 s`，使用基础虚拟储能预设和 `10 s` 结算步长。每个候选完整评价正常、重车晚点120秒、空车晚点120秒、重车晚点300秒和空车晚点300秒共5个场景。

工具执行一次预热、一次 `cProfile` 评价和三次非剖析计时，输出原始 profile、机器可读摘要和中文报告。每次评价同时计算只包含业务结果的语义 SHA-256。

## 2. 优化前热点

8列车候选优化前的三次非剖析耗时为 `6.227-6.281 s`，中位数 `6.261449 s`。单次 `cProfile` 耗时为 `12.653986 s`，主要累计热点如下：

| 模块或函数 | 调用次数 | 累计耗时/s | 判断 |
| --- | ---: | ---: | --- |
| 能量结算 `settle` | 5 | 5.678 | 主要模块 |
| 时空网络构建 | 5 | 2.874 | 主要模块 |
| 能量桶结算 | 15545 | 2.772 | 结算核心计算 |
| 时空弧能量积分 | 1400 | 2.253 | 同车型相同弧存在重复 |
| 信号约束检查 | 10 | 2.112 | 主要模块 |
| 供电臂限值解析 | 379700 | 1.233 | 同一 ID 大量重复解析 |
| 资源约束检查 | 5 | 1.144 | 主要模块 |

累计耗时包含下级函数，表中数值不能相加。剖析器本身会放大 Python 函数调用成本，因此是否保留优化以非剖析重复计时为准。

## 3. 已实施的等价优化

### 单次结算内缓存供电臂解析

一个候选中供电臂 ID 种类有限，但每个功率样本和能量桶都会重复执行字符串清理、组合 ID 校验和显式配置判断。现以原始供电臂 ID 为键，在一次 `settle` 调用内缓存解析结果；缓存不会跨候选或跨结算存在，供电臂配置变化不会被旧结果污染。

优化后，底层 `limit_for_power_arm` 和 `power_arm_limit_is_explicit` 的调用次数均由数十万次降至310次。外层局部缓存函数仍按原调用位置执行，但只做字典读取。

### 单次网络内复用相同弧能量

同车型多列车共享基础轨迹且站间边界相同时，弧能量只取决于轨迹对象和轨迹内起止时刻。现仅在一次 `build_time_space_network` 调用内缓存该积分结果。时间相关条件生成不同轨迹对象时不会错误复用。

8列车、5场景下，实际弧能量积分次数由1400次降至663次，时空网络累计剖析耗时由 `2.874 s` 降至 `1.750 s`。

## 6. 剩余瓶颈与停止条件

优化后单次 `cProfile` 中，剩余主要热点为：

- 能量结算累计 `4.129 s`，其中能量桶结算累计 `2.737 s`；
- 信号检查累计 `2.099 s`；
- 时空网络累计 `1.750 s`；
- 资源穿越时刻计算自身耗时 `1.550 s`；
- 资源检查累计 `1.162 s`。

这些热点涉及逐时间桶能量因果、动态安全距离、运行轨迹插值和资源占用边界，继续优化需要更强的结构性缓存或算法改写。当前没有发现新的、大量重复且可直接证明等价的低风险点。因此第四阶段到此停止，不为追求微小性能收益改变结算或安全约束语义。

若后续需要扩大到更多列车、更大搜索预算或更多扰动场景，下一阶段应先设计增量评价：复用未变化列车的轨迹、资源区间和能量桶贡献，并单独建立等价性测试。正式数据到位后需用相同工具重新剖析。
