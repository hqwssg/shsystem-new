# 朔黄铁路重空协同与再生制动能量优化项目总览

## 1. 项目是什么

本项目是一个面向朔黄铁路的算法原型，解决两个问题：

1. 计算列车牵引、制动和再生能量，并评估再生能量能够被吸收、储存和再次利用的程度；
2. 调整重车/空车发车时刻和运行图，在不违反运输及电气约束的前提下改善能量利用。

它不是实时控制系统，也不是完整的铁路低碳平台。

## 2. 当前算法边界

### 包含

- 单列车运行和牵引/制动功率仿真；
- 再生制动能量结算；
- 储能容量、充放电功率、效率和 SOC 约束；
- 储能放电为牵引负荷提供部分能量；
- 重车/空车运输任务、OD、运行图和发车相位优化；
- 站场、区间、闭塞、追踪间隔和供电臂约束检查；
- 候选方案、基线对比、结果审计和可解释输出。

### 不包含

- 车载牵引/制动底层控制；
- 现场信号联锁和安全认证；
- 实时位置、功率、SOC 采集及控制指令下发；
- 储能设备选型、土建、电气设计和投资决策；
- 碳排放平台、通用 AI 预测和三维可视化。

## 3. 能量模型口径

当前主场景为 `storage_no_direct`：

```text
再生能量不能在同一时间直接发送给另一列牵引列车；
再生能量只能在允许的储能区段进入储能；
储能中已有电量可以向牵引负荷放电；
同一时间桶中新充入的能量不能立即放电；
无法吸收的部分计为弃能。
```

牵引需求的能量来源为：

```text
储能放电 + 电网供能
```

储能放电受 SOC、容量、最大放电功率、区段位置和效率限制。当前没有单独优化储能停留时间、自放电、辅助功耗或寿命衰减，因为正式设备参数尚未取得。

## 4. 调度优化逻辑

优化器生成运行图候选，检查时间单调性、到发一致性、运行方向、站场/区间资源、闭塞和追踪间隔，再调用能量结算评价候选。

主要目标是：

- 减少弃用再生能量；
- 减少电网购电量；
- 减少运行图调整和延误；
- 保证资源和电气约束可行。

算法先评估输入运行图作为基线，再决定是否值得优化。候选只有在满足硬约束、且有效再生损失或电网购电量至少一项超过数值容差改善、另一项没有明显恶化时，才会得到 `optimization_decision.action=optimize`。没有实质改善时得到 `keep_baseline`，保留原运行图，并记录 `no_material_energy_improvement`。

不可行候选不能因为能量指标较好而进入最终 Pareto 结果。`candidate_explanations.csv` 用于说明候选为何进入或未进入 Pareto 集。

## 5. 当前数据和成熟度

程序、算法流程、测试和审计体系已经基本形成，但输入仍是部分真实线路资料与规划/虚拟/启发式参数的混合数据。

仍需正式确认：

- 车辆质量、牵引力、制动力、牵引/制动曲线和 Davis 阻力；
- 正式运行图、运输任务和 OD；
- 供电臂边界、牵引供电能力和再生吸收能力；
- 储能容量、功率、效率、SOC 范围、成本和接入区段；
- 闭塞分区、站场咽喉、股道、区间容量和追踪规则；
- 初始车流库存及智能电表方向、站区间映射和质量信息。

## 6. 结果能否使用

当前结果可以用于：

- 验证代码和流程；
- 检查能量守恒、SOC 和运输约束；
- 比较不同候选方案的相对差异；
- 进行参数区间和鲁棒性分析。

当前结果不能直接用于：

- 发布正式节能率或绝对能耗；
- 确定储能容量、数量或设备型号；
- 计算正式投资收益；
- 证明现场运行图已经可以执行。

## 7. 正式数据到位后的流程

```text
接收正式数据和来源证明
→ 数据门禁与字段校验
→ 替换规划/虚拟参数
→ 重建派生数据
→ 运行测试和能量审计
→ 重跑基线与优化方案
→ 与实测或正式运行图对比
```

## 8. 最终定位

> 项目已经具备算法原型和验证框架，当前处于等待正式工程数据接入、标定和现场对比的阶段；不能把现有混合数据结果当作正式工程结论。
