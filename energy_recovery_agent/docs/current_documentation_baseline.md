## 1. 本文的权威性

本文是项目文档的唯一当前状态入口。其他文档中的阶段日期、旧测试数量、旧性能数字和失败案例用于说明演进过程，不得覆盖本文的当前结论。

文档状态由 `document_status_registry.json` 管理：

- `current_authority`：可以直接用于判断当前项目状态；
- `current_supporting`：当前仍有效的使用说明或数据字典；
- `technical_evidence`：专项方法、实验和历史演进证据，不单独代表当前总体状态；
- `superseded_summary`：已经被本文或当前权威文档取代的旧摘要；
- `research`：论文材料，不属于算法软件交付结论；
- `reference`：来源原件或背景资料，不等于当前实现；
- `archive`：历史记录，不作为当前依据。

## 2. 当前项目结论

项目只交付两项算法能力：再生制动能量回收能力分析，以及重车/空车调度与运行图优化。当前主场景为 `storage_no_direct`：再生能量不能直接抵扣同一时刻牵引负荷，只能在允许区段进入储能；储能已有能量可以向后续牵引负荷放电。

算法、数据库任务闭环、异常防护、滚动恢复、结果审计、发布门禁和本地生产保障已经形成。当前没有已确认但尚未修复的确定性算法缺陷，也没有基于占位参数继续修改核心物理模型的合理依据。

日常维护和发布流程已经统一自动化：维护总控持续核验CI、文件卫生和四类当前交付包；发布总控依次执行候选检查、基线冻结、原子构建、软件成分安全门禁、短测和长测。构建支持互斥锁、失败回滚和固定时间可复现ZIP。
