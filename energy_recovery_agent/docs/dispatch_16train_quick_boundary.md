# 16列车快速档边界测试

更新时间：2026-09-06

## 1. 测试目的与口径

本轮在12列车定向修复重复检查优化完成后，按冻结的4×1搜索预算、`seed=11`、单线程、10秒结算步长和5个扰动场景执行8重+8空快速档。两个口径分开解释：

- E16：25200秒扩展时域、3300秒基准重空间隔，用于隔离16列车计算规模；
- F16：14400秒固定时域、1800秒基准重空间隔，用于评价运输任务密度和资源可行域。

两例超时门限均为1200秒。当前数据含规划和工程占位参数，结果不是正式线路容量。

## 2. 结果

| 指标 | E16扩展时域 | F16固定时域 |
| --- | ---: | ---: |
| 列车数 | 8重+8空 | 8重+8空 |
| 端到端耗时 | 256.626418 s | 258.270180 s |
| 1200秒门限占比 | 21.4% | 21.5% |
| 峰值进程树内存 | 158.062 MB | 150.008 MB |
| 服务数量完整 | 是 | 是 |
| 候选数/核心稳健可行候选 | 16/0 | 18/0 |
| 核心稳健可行 | 否 | 否 |
| 标称回退 | 是 | 是 |
| 基线→返回方案资源冲突 | 4→8 | 16→7 |
| 基线→返回方案约束违反度 | 0.395145→0.133694 | 0.197209→0.059609 |
| 语义SHA-256 | `9ca5c6b1...94f8fd6` | `fab634d5...37952b3` |

两例均正常结束、结果有效、服务完整且远低于性能门限。因此当前“计算完成的已测试上限”由12列车推进到16列车，不触发增量评价或并行架构重构。

两例均没有核心稳健可行候选，返回方案仍有阻塞级咽喉进路冲突。因此“核心稳健可行的已测试上限”仍为12列车。返回方案的购电、弃能、回收率和成本变化只用于诊断搜索方向，不能作为可实施节能收益。

## 3. 可行域诊断

两例都已触发原有全局修复和冲突驱动局部修复，不是因为修复器未运行：

| 诊断 | E16 | F16 |
| --- | ---: | ---: |
| 全局修复评价模板 | 21 | 20 |
| 局部修复评价模板 | 926 | 706 |
| 局部修复迭代 | 8/8 | 8/8 |
| 找到资源可行种子 | 0 | 0 |
| 最优局部评分变化 | `(2,7,605.99,0)`→`(1,5,270.79,1080)` | `(3,11,361.09,0)`→`(3,9,446.86,420)` |

E16局部修复将核心阻塞场景数从2降到1，但在当前最大600秒逐列车调整和束宽6下仍未闭合最后一个场景。F16三个核心场景始终阻塞，固定时域密度压力更强。该证据只能说明当前快速档搜索及修复边界，尚不能证明当前资源模型下不存在16列车稳健可行运行图。

## 4. 当前边界与下一步

- 计算完成的已测试上限：16列车；
- 核心稳健可行的已测试上限：12列车；
- 性能架构优化：当前不需要，E16/F16只占门限约21%；
- 能源收益结论：16列车返回方案不可执行，不能报告为节能方案。

E16资源可行域定向诊断及第二级修复已经完成：默认60秒/8轮修复遗漏了窄累计路径，30秒/16轮在不扩大600秒单车上限和束宽的情况下找到核心稳健可行种子，并通过完整评价。该配置现已限定为16列车及以上、常规修复失败后的第二级修复。完整E16验证找到5个核心稳健可行候选；F16也正确触发第二级修复，但固定时域高密度场景仍无核心稳健可行候选。12列车回归保持第一级修复参数。专项说明见 `docs/dispatch_e16_feasibility_diagnosis.md`。

2026-09-07精确资源可行性复核修正了F16结论：相同F16定义域内存在通过三个核心场景完整资源检查的整数秒方案，故本文件的F16“未找到”只代表快速档和第二级启发式的历史搜索边界，不代表当前资源模型不可行。最新结论见 `docs/exact_resource_feasibility.md`。
