# F16高密度资源冲突定位、启发式边界与精确复核

## 1. 诊断目的

F16表示固定14400秒预测时域内的8列重车与8列空车场景。第二级资源修复正确触发，但当时没有找到核心稳健可行候选。后续精确资源可行性层已经找到并验证可行解。本诊断用于回答三个问题：

1. 失败是否来自单一相位点或搜索粒度遗漏；
2. 失败是否主要来自固定时域下的运输密度与核心扰动叠加。
3. 启发式“未找到”究竟是搜索漏解还是模型确实无解。

第2至第3节保留启发式阶段的历史诊断；第4节给出当前精确复核结论。资源可行解仍不等于能耗最优解，不能直接据此宣称节能收益。

## 2. F16直接冲突定位

F16完整输出位于 `paper/experiments/dispatch_phase10_level2_f16/`。

基线资源冲突全部为 `throat_route_conflict`，主要集中在：

| 计划 | 主要咽喉 | 典型冲突列车 | 冲突特征 |
| --- | --- | --- | --- |
| 基线 | 南湾、定州东、三汲 | H006/H007/H008与E001/E002/E003；E003-E008与H001-H006 | 反向重空进路在同一咽喉占用窗口重叠 |
| 优化返回方案 | 定州西 | E002-E008与H001-H007 | 冲突由多个位置收敛到定州西，但仍为阻塞级咽喉进路冲突 |
| 第二级最佳局部候选 | 蠡县 | E004/E005/E007/E008与H001-H005 | 正常场景仍有4个冲突，空车轻度延迟场景仍有3个冲突 |

F16选中返回方案的核心场景结果为：

| 场景 | 资源冲突数 | 约束违反度 | 是否阻塞核心可行性 |
| --- | ---: | ---: | :---: |
| normal | 7 | 0.059609 | 是 |
| heavy_delay_light | 11 | 0.500349 | 是 |
| empty_delay_light | 13 | 0.946733 | 是 |

非核心的±300秒强扰动场景也存在冲突，但它们不改变本轮核心结论。F16没有出现电气约束、SOC缺口或服务数量截断导致的失败，失败来源明确是资源层咽喉进路冲突。

## 3. 搜索覆盖诊断

### 3.1 固定时域全局相位扫描

在14400秒时域内，以30秒相位步长扫描1500、1800、2100、2400秒重空追踪间隔组合，共评价244个模板，结果为0个三核心场景资源可行模板。

最接近的组合是重空均为1800秒、空车相位约1590秒，但三个核心场景仍分别存在5、1、5个冲突。由此排除了“只差一个60秒相位点”这一解释。

### 3.2 时域扩展对照

保持8重+8空、资源模型和核心扰动不变，只增加可用时域并重新扫描：

| 时域 | 扫描间隔组合 | 扫描模板数 | 三核心场景资源可行模板 | 最佳结果 |
| ---: | --- | ---: | ---: | --- |
| 14400秒 | 1500/1800/2100/2400秒 | 244 | 0 | 三个核心场景均阻塞 |
| 16200秒 | 1800/2100/2400/2700秒 | 224 | 0 | 三个核心场景均阻塞 |
| 18000秒 | 1800/2100/2400/2700/3000秒 | 489 | 0 | 仅正常、重车轻度延迟场景阻塞；空车轻度延迟场景可行 |
| 21600秒 | 2100/2400/2700/3000/3300秒 | 816 | 0 | 最佳点可消除正常场景冲突，但两个延迟场景仍阻塞 |

## 4. 精确复核与当前判断

新增精确资源可行性层后，保持8重+8空、14400秒时域、1800秒重空间隔、1590秒相位和三个核心扰动场景不变，在完整 `[0, 14400]` 整数秒发车域内求解。模型在23.229秒内找到候选，现有完整资源检查器复核结果为：

| 场景 | 资源冲突数 | 重叠违反量 | 流连续性 |
| --- | ---: | ---: | :---: |
| normal | 0 | 0秒 | 通过 |
| heavy_delay_light | 0 | 0秒 | 通过 |
| empty_delay_light | 0 | 0秒 | 通过 |

因此当前结论是：

> F16在当前规划/占位资源模型和明确发车域内存在核心稳健资源可行运行图；此前结果是启发式搜索漏解，不是模型结构性不可行。

精确层使用容量1资源松弛进行搜索，但任何候选都必须通过包含全部资源的权威检查器后才能标记为可行。若松弛模型被证明不可行，才可在显式定义域内推出完整模型不可行；达到时限没有解只能标记为未知。

## 5. 历史边界解释

当前规划/占位资源模型下，F16的主要瓶颈是：

1. 8重+8空在14400秒固定时域中的运行密度较高；
2. 重车和空车反向进路在多个咽喉形成周期性叠加；
3. `heavy_delay_light`扰动会把原本接近的咽喉占用窗口进一步推入冲突；
4. 第一级和第二级修复只能调整发车时刻，不能增加咽喉容量、改变联锁进路规则或放宽核心鲁棒约束。

上述密度、周期性咽喉叠加和局部修复表达能力限制，仍可解释启发式为何难以命中可行域，但不再支持“F16是当前模型不可行边界”的判断。它证明的是第二级启发式覆盖了较宽邻域后仍会漏掉非局部、非均匀的逐车错峰组合。

## 6. 对项目的处理结论

- 保留第二级修复：总列车数达到16列车及以上且第一级修复失败时触发30秒/16轮/束宽6搜索。
- 不继续盲目扩大启发式层级：16列车及以上由精确层负责验证或补解，避免把搜索失败误判为模型无解。
- 精确层候选作为资源可行种子进入现有完整稳健评价；只有完整评价通过的候选才可进入可实施方案比较。
- F16端到端复验中，该种子与5种虚拟储能预设组合后均通过三个核心场景完整评价；终端SOC软偏差和±300秒非核心压力场景失败仍需单独披露。
- 后续词典序质量求解直接以相位840秒原运行图为参照，将最大单车偏移从4013秒降至经证明最优的367秒，总绝对偏移从33973秒降至3000秒，且完整核心门禁保持通过。
- 正式闭塞分区、咽喉进路锁闭、咽喉容量、站场作业和真实运行图数据到位后，必须重新运行本诊断。
- 若正式数据仍显示F16冲突，应由运输组织方案决定降低任务密度、扩大时域、调整追踪间隔或增加可用进路资源；这些属于运行图和基础设施约束决策，不应全部塞入能量回收优化器。
