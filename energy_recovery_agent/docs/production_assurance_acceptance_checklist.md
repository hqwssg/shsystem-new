# 生产运行保障验收清单

## A. 本地可独立完成

- [ ] 正式算法源码基线、目录包和ZIP校验通过；
- [ ] `production_assurance_policy.json`结构与版本检查通过；
- [ ] 生产预检`local_ready=true`且`production_accepted=false`；
- [ ] 算法运行准备度、短测和长测性能门禁通过；
- [ ] 监控快照可输出队列、心跳、租约、失败率、容量和磁盘指标；
- [ ] 告警边界、失败率最小样本和退出码专项测试通过；
- [ ] 本地PostgreSQL备份可读取、可恢复且关键行数一致；
- [ ] 恢复工具拒绝业务库名、非法名称和覆盖已有恢复库；
- [ ] 事故响应、启动停止、升级回滚和证据归档步骤齐全；
- [ ] 生产保障工具包目录与ZIP逐文件SHA-256一致。

## B. 必须在甲方目标环境完成

- [ ] 目标服务器、正式数据库和网络路径部署完成；
- [ ] TLS证书有效，四类登录账号按最小权限分离；
- [ ] 连接串由密钥系统注入，日志和交付包不含凭据；
- [ ] 甲方监控平台已读取告警JSON并实测通知到达；
- [ ] 正式备份介质完成恢复演练，RPO、RTO和保留周期获批准；
- [ ] 目标并发负载、连接池、磁盘/WAL和数据库重启故障演练通过；
- [ ] worker由正式进程管理器托管并验证自动重启和优雅停止；
- [ ] 平台五类任务、状态、结果、工件下载和审计联调通过；
- [ ] 不可行扣留与人工接管流程由调度业务负责人确认；
- [ ] 值守人员、事故联系人、升级链和维护窗口获得签字。

## C. 判定规则

本地A项全部通过时只能形成“部署前准备完成”。只有A、B两组全部完成且证据归档后，才允许由责任方把生产状态改为`accepted`。任何脚本都不会在缺少B组证据时自动声明生产验收通过。
