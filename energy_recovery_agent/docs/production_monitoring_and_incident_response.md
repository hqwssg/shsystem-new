# 生产监控、告警与事故响应

## 1. 监控合同

机器入口为`tools/production_operations_snapshot.py`，阈值位于`operations/production_assurance_policy.json`。当前策略是部署前基线，目标环境必须依据正式任务到达率、最长算法耗时、磁盘预算和甲方值守要求重新批准。

| 指标 | 含义 | 当前Warning/Critical | 首要动作 |
| --- | --- | --- | --- |
| `pending_count` | 排队任务数 | 50 / 200 | 核对worker、到达率和数据库锁 |
| `oldest_pending_age_s` | 最老任务等待秒数 | 300 / 900 | 判断容量不足或worker不可用 |
| `stale_heartbeat_age_s` | 活动任务最大心跳年龄 | 120 / 300 | 核对worker进程和网络 |
| `expired_active_lease_count` | 已过期但仍活动的租约 | 1 / 1 | 阻止旧worker写回并安全回收 |
| `recent_failure_rate` | 24小时成功/失败任务中的失败率；主动取消不计入分母 | 5% / 15% | 最少10个样本后生效 |
| `database_size_bytes` | 数据库总大小 | 50 / 100 GiB | 检查工件保留和备份窗口 |
| `artifact_size_bytes` | 数据库内工件逻辑大小 | 40 / 80 GiB | 执行经批准的保留策略 |
| `host_disk_free_percent` | 项目盘剩余比例 | 20% / 10% | 停止大任务并释放已批准空间 |

`critical`应使命令返回非零；`warning`默认记录但不阻断，可用`--fail-on warning`提高门槛。报告不保存数据库连接串。

## 2. 告警路由

- Warning：算法运维在当班内确认，记录原因和趋势；不自动删除数据或扩容。
- Critical：立即通知平台管理员和算法运维，暂停新增高成本任务；涉及数据库、TLS或容量时通知数据库管理员。
- `withheld_infeasible`或`manual_intervention_required`：同时通知调度业务负责人，不得由运维绕过算法提交门禁。
- 数据泄露、账号异常或证书问题：立即停用受影响凭据并通知安全负责人，不在普通日志中粘贴连接串。

甲方未确认通知渠道前，只能验证告警JSON和退出码，不能声称短信、邮件或值班系统已接通。

数据库表只记录活动任务心跳，无法证明没有任务时的空闲worker仍存活；该项必须由Windows服务、systemd、容器编排或甲方进程管理器直接监控进程并提供独立告警。

## 3. 事故分级

| 等级 | 例子 | 初始响应目标（待甲方确认） |
| --- | --- | --- |
| P1 | 数据损坏、错误计划被下发、安全凭据泄露、数据库不可用 | 立即停止写入和任务下发，保全证据并升级负责人 |
| P2 | worker全部不可用、队列Critical、持续失败率Critical | 暂停新任务，恢复服务或切换已批准回退方案 |
| P3 | 单任务失败、单worker重启、容量Warning | 当班分析并跟踪趋势 |

表中的响应目标是处置顺序，不是已承诺SLA。

## 4. 标准处置流程

1. 确认告警时间、策略版本、数据库时间和受影响任务ID。
2. 保存运行快照、worker日志、状态事件和包哈希；不得先清理现场。
3. 判断是输入、算法不可行、资源超时、数据库、网络还是平台展示问题。
4. 采取最小影响措施：暂停新任务、停止单个worker、取消明确任务或回收已确认过期租约。
5. 禁止绕过幂等键、租约令牌、结果事务和`withheld_infeasible`门禁。
6. 恢复后运行健康检查和代表性任务，确认没有旧结果串用。
7. 记录根因、影响范围、恢复时间和防复发事项。

## 5. 常见故障决策

- 心跳过期但进程仍在：先隔离旧进程，确认不再运行后再回收任务。
- 数据库连接失败：检查TLS、DNS、连接池和数据库状态；不得切换到不安全连接串。
- 磁盘Critical：暂停生成大工件的任务，按批准的保留策略处理；不得临时删除数据库目录或WAL。
- 失败率高：按`error_message`和运行日志聚类；正式数据问题与算法软件错误分开统计。
- 性能门禁失败：阻止新版本发布，比较同机同输入的中位耗时和峰值RSS，不通过降低测试规模放行。
- 结果不可行：保留冲突和候选详情，按业务规则等待新观测或人工接管，不把不可行等同于程序失败。
