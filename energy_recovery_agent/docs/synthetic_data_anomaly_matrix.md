# 合成输入数据异常覆盖矩阵

更新时间：2026-09-09

## 1. 目的

本矩阵用于验证平台、数据库或文件提供的异常输入，能否在进入能量结算、运行图优化和重空调度算法之前被统一数据质量入口拦截。它补充了算法场景回归和实时状态异常测试，重点检查静态数据包自身的格式、数值、拓扑和跨表一致性。

统一命令：

```powershell
python run_project.py test-synthetic-data-anomalies
```

默认以 `data/real_shuohuang/` 的当前有效数据包为母本，结果写入 `paper/experiments/synthetic_data_anomaly_matrix_current/`。每个案例都在独立临时副本中注入单一异常，不修改母本。

## 2. 覆盖范围

| 类别 | 数量 | 主要异常 | 验证目的 |
| --- | ---: | --- | --- |
| 文件与模式 | 4 | 缺文件、损坏JSON、缺CSV列、非法信号制式 | 阻止不完整或不可解析的数据包进入算法 |
| 线路与拓扑 | 10 | 线路长度、重复/越界车站、区段缺口/重叠、非法范围、NaN、能量区和闭塞方向 | 保证线路空间连续且区间、方向和效率可解释 |
| 车辆物理 | 5 | 重复车型、零/负牵引制动、非法方向、黏着比例越界 | 阻止不可运行或物理边界错误的车辆参数 |
| 储能与电气 | 5 | 负容量/功率、效率越界、非法布尔值、运行条件结构错误 | 保证储能结算参数及条件结构满足计算前提 |
| 资源与跨表 | 5 | 未知车站引用、零容量、负追踪间隔、非法列车类型 | 保证站场、作业和追踪约束能够正确关联 |

当前共29项异常案例。有效母本本身也必须通过校验，所有异常必须同时满足：数据包被判无效、出现预期错误码、错误定位到预期文件。

## 3. 输出

| 文件 | 用途 |
| --- | --- |
| `SYNTHETIC_DATA_ANOMALY_REPORT.md` | 按类别查看每项异常、预期错误码、实际错误码和结果 |
| `synthetic_data_anomaly_summary.json` | 总状态、分类计数、母本完整性和案例集合指纹 |
| `synthetic_data_anomaly_cases.csv` | 逐案例记录，便于CI、论文附表和平台验收引用 |
| `synthetic_data_anomaly_failures.json` | 只记录失败案例，便于定位漏检或错误码漂移 |

`case_set_sha256` 由稳定案例字段生成，可用于确认两次测试是否执行了同一组异常。`baseline_unchanged=true` 表示测试前后的母本目录哈希一致。

## 4. 与其他测试的关系

| 测试 | 检查对象 |
| --- | --- |
| 合成场景回归 | 正常及边界业务场景下的算法输出是否回归 |
| 随机合成差分 | 生产算法与独立参考实现是否一致 |
| 实时状态异常矩阵 | 在线消息乱序、断流、坏状态和恢复行为 |
| 本矩阵 | 静态输入数据包在算法执行前是否被质量门禁拦截 |

## 5. 当前边界

本矩阵证明的是软件校验覆盖，不证明母本中的工程占位参数已经正式标定。它也不能替代数据库字段约束测试、平台接口并发测试、正式数据统计分布异常检测和现场联调。正式数据到位后，应在保留这29项通用案例的基础上，增加针对甲方字段、单位、枚举值和跨表主键的项目专属异常。
