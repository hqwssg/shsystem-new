# 算法边界、能力回收定义与交付物

更新时间：2026-09-01

本文冻结当前算法项目的实现边界和结果口径。项目只负责再生制动能量回收能力分析与重空列车调度优化；技术方案中的监测硬件、实时控制、碳排放平台和通用可视化不属于本算法交付物。

## 1. 项目目标

在给定线路、列车、运行图、供电臂、储能和运输任务条件下，计算再生制动能量的可回收能力，并通过重车/空车协同、发车时间和运行图调整，提高可利用再生能量、减少弃电或降低结算后的综合能量损失，同时满足运输、资源、车流连续性和电气约束。

## 2. 算法负责范围

### 2.1 能量回收能力

- 列车牵引和制动功率序列生成；
- 再生能量产生量计算；
- 按时间片、方向和供电臂进行能量匹配；
- 储能充电、放电、SOC、容量、功率和效率约束；
- 弃电、储能损失、电网供能和终端 SOC 影响结算；
- 分列车、分区段、分供电臂和分时间片的能量账本；
- 回收能力、瓶颈和限制原因分析。

### 2.2 列车调度优化

- 重车、空车的发车时刻和相位优化；
- 运行图候选生成和方案比较；
- 重空车流连续性和库存约束；
- 区间、站场、咽喉、追踪间隔等已建模资源约束；
- 能量目标与运输能力、延误、冲突惩罚等目标的联合评价；
- 基线、优化方案、候选集和 Pareto 结果输出；
- 约束冲突、不可行原因和结果质量审计。

## 3. 不属于本算法的范围

以下内容由现场系统、设备系统或其他项目负责，不在本项目中实现为算法功能：

- 车载或地面能耗监测硬件及其驱动；
- 20 Hz 运行状态采集设备及现场部署；
- 实时列车位置、功率、SOC 数据接口；
- 机车底层牵引/制动控制和储能控制器控制指令；
- 信号联锁、闭塞设备和安全认证系统；
- 生产调度指挥系统和控制指令下发；
- 碳排放核算平台、LSTM 预测、通用异常检测平台；
- 三维可视化平台和生产级前端系统；
- 储能设备选型、土建、电气设计和投资决策。

上述系统可以向本算法提供数据，或消费本算法生成的方案与指标，但不应与本项目的算法模块混为一体。

## 4. 能力回收的统一定义

“能力回收”不是单一的节能率，而是从理论再生到调度可实现效果的分层结果：

| 层级 | 定义 | 主要限制 |
| --- | --- | --- |
| 理论再生能力 | 列车制动工况在给定运行轨迹下可产生的再生能量/功率 | 列车动力学、制动策略 |
| 供电可接纳能力 | 在同一时间片、同一方向/供电臂规则下可被牵引侧或系统接纳的能量 | 供电臂、电气限值、时空匹配 |
| 储能可吸收能力 | 在储能容量、充电功率、SOC 和效率约束下可实际吸收的能量 | 储能设备参数和 SOC |
| 调度可实现回收能力 | 通过改变重空列车时刻、相位或运行组织后，实际增加的有效回收量 | 运输任务、资源、车流连续性、运行图约束 |

默认主场景 `storage_no_direct` 下，上下行不进行直接互供；因此 `direct_used_kwh` 为 0，回收主要通过允许的储能区段完成。其他直供场景属于研究扩展，不是当前默认工程口径。

## 5. 指标口径

核心指标按以下含义使用：

- `total_gen_kwh`：列车产生的再生侧总能量；
- `accepted_by_power_arm_kwh`：通过供电臂和时间匹配后被系统接纳的能量；如当前输出未单列，则由直接利用和储能输入等明细解释；
- `battery_charge_kwh`：储能输入侧实际充电量；
- `battery_discharge_kwh`：储能输出侧实际放电量；
- `direct_used_kwh`：同一供电臂、同一时间片直接利用的能量；当前主场景为 0；
- `recovered_energy_kwh`：按项目发布口径计入有效回收的能量，应在报告中明确采用储能输入侧还是输出侧定义；
- `wasted_kwh`：未被直接利用或储能吸收的再生能量；
- `grid_kwh`：结算后仍由电网提供的牵引能量；
- `effective_regen_loss_kwh`：弃电、储能转换损失和终端 SOC 影响折算后的综合再生损失；
- `energy_term` / `energy_objective_kwh`：当前主优化口径，通常为 `grid_kwh + effective_regen_loss_kwh`；
- `recovery_rate`：回收量与理论再生量的比值，必须同时注明回收量的侧别和统计范围；
- `feasible`：方案是否满足当前模型中的运输、资源、车流和电气约束。

“回收率”“弃电减少率”“电网购电减少率”必须分开报告，不能用其中一个指标替代另外两个指标。

当前代码已在 `SettlementResult`、重空调调度 KPI 和运行图审查汇总中提供 `accepted_by_power_arm_kwh`、`recovered_energy_kwh` 和 `recovery_rate`。结果审计会检查三者之间的守恒关系、效率折算关系和 [0, 1] 范围。其中有效回收量采用“直接利用量 + 储能充电量 × 储能效率”的输出侧口径。

## 6. 能量账本约束

在同一统计范围内，至少应满足：

```text
total_gen_kwh = direct_used_kwh + battery_charge_kwh + wasted_kwh
```

储能充电量和放电量不能直接视为同一批等量能量；二者之间必须体现储能效率、SOC 边界和时间顺序。调度收益只能在固定车辆、储能、供电臂和评价范围下，与基线比较后归因。

## 7. 当前交付物

### 7.1 算法和程序

- 能量结算与回收能力分析模块；
- 列车运行/功率序列计算模块；
- 重空列双层时空网络和候选调度模块；
- 运行图审查与候选优化模块；
- 资源、车流连续性和电气约束检查模块；
- 结果质量审计和运行可追溯清单模块；
- 优化收益归因、候选筛选和瓶颈解释模块；
- `run_project.py` 统一命令入口。

### 7.2 数据和配置

- 线路、站点、区段、供电臂、储能、车辆和资源输入模板；
- 数据质量校验和正式数据接入门禁；
- 运行图和重空运输任务模板；
- 参数版本、输入快照和 SHA-256 追溯信息。

### 7.3 结果和验证材料

- 基线与优化方案 KPI；
- 能量时间线和分项能量账本；
- 候选方案、Pareto 集和不可行原因；
- 是否采用的机器决策、KPI 收益归因、候选筛选漏斗、瓶颈聚合和维度变化明细；
- 运行图能量审查报告；
- 数据质量报告和结果审计报告；
- 合成场景、回归、鲁棒性、性能和复现报告。

## 8. 正式数据到位后的验收

正式数据替换后，需重新验证车辆动力学、供电臂、储能和调度约束，并至少完成：数据接入门禁、完整 smoke、CI、固定种子重复运行、结果审计、基线对比和参数来源复核。只有通过这些步骤后，才可发布正式节能、回收能力或储能容量结论。
