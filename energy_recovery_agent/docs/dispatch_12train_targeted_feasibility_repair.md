# 12列车资源冲突诊断与定向可行性修复

更新时间：2026-09-06

## 1. 问题与诊断结论

修复前，F12固定时域和E12扩展时域均能在720秒内完成，但没有核心稳健可行候选，只能返回含咽喉进路冲突的标称方案。原修复器只能调整统一重车间隔、统一空车间隔和全局相位，不能表达某一列车的局部错峰。

F12进一步扫描1096个均匀模板，耗时1010.34秒，仍未发现核心稳健资源可行模板。最接近可行的模板为重空间隔 `2100/2100 s`、相位 `1590 s`，三个核心场景合计只剩2个冲突、60秒重叠。由此可以确定：瓶颈不是资源检查缺失，也不是简单相位粒度不足，而是均匀模板缺少逐列车局部调整能力。

## 2. 修复机制

`ScheduleTemplate` 新增重车和空车逐列车发车微调元组。普通NSGA-II搜索不变异这两个字段；只有常规搜索和全局修复均未找到稳健可行候选时，才执行以下流程：

1. 12列车及以上使用稀疏全局相位锚点，避免宽网格资源扫描超过主搜索成本；
2. 对正常、重车晚点120秒、空车晚点120秒三个核心场景执行原资源检查；
3. 从阻塞冲突中提取涉及的列车编号和重叠时长；
4. 以60秒为步长，围绕冲突列车生成局部提前/延后邻域；
5. 使用束宽6、最多8轮的确定性束搜索，优先减少阻塞场景数、冲突数和重叠时间；
6. 找到资源可行种子后，对各储能预设执行完整五场景能量、电气、信号、资源和服务数量评价。

局部微调绝不绕过原约束。负发车时刻、列车顺序变化、服务数量缺失以及任何核心场景资源冲突仍会被拒绝。

## 3. 最终实测结果

统一条件为4×1搜索、`seed=11`、单线程、10秒结算步长和5个扰动场景。

| 指标 | F12固定时域 | E12扩展时域 |
| --- | ---: | ---: |
| 时域 | 14400 s | 18000 s |
| 端到端耗时 | 388.498929 s | 609.858808 s |
| 720秒门限占比 | 54.0% | 84.7% |
| 峰值进程树内存 | 139.258 MB | 151.062 MB |
| 候选数/稳健可行候选数 | 22/5 | 21/5 |
| 资源冲突数 | 6→0 | 2→0 |
| 约束违反度 | 0.127169→0 | 0.197572→0 |
| 标称回退 | 否 | 否 |
| 电网购电变化 | -6.718% | -7.383% |
| 弃能变化 | -3.317% | -3.850% |
| 回收率 | 0.0367→0.0653 | 0.0367→0.0699 |
| 总成本变化 | -1.368% | -1.439% |

F12选中模板为重空间隔 `2100/2100 s`、相位 `1590 s`，仅将第6列空车延后240秒。E12选中模板为重空间隔 `3300/3300 s`、相位 `540 s`，对部分重空列车作 `-180～+180 s` 局部调整。两个种子在5个储能预设下均通过完整稳健评价。

最终证据位于 `paper/experiments/dispatch_extended_scale_phase7_beam6/`。资源诊断和独立探针结果位于 `paper/experiments/dispatch_12train_resource_probe/`。

## 4. 当前边界与下一步

当前规划/占位参数下，计算完成和核心稳健可行的已测试上限均推进到12列车，但这不是正式线路容量。正式咽喉、闭塞、车辆、运行图和运输任务数据到位后必须重新扫描和校准。

上述609.86秒是重复资源检查优化前的历史基线。后续剖析确认，相邻模板反复计算同一轨迹的站点穿越时刻和首次储能入口时刻是主要成本。增加区分时间相关/时间无关工况的严格等价缓存后，独立定向修复由252.84秒降至7.57秒，完整E12由609.86秒降至152.67秒；语义SHA、候选数、稳健可行性和全部能源指标保持一致。

E12目前只占720秒门限21.2%，定向修复重复资源检查任务已经完成，没有必要继续微调该缓存。F12共享路径复验也由388.50秒降至152.63秒，并保持语义一致；71个 smoke 脚本全部通过。后续E16/F16快速档已完成，当前结论和下一步见 `docs/dispatch_16train_quick_boundary.md`；本阶段专项证据和停止条件见 `docs/dispatch_targeted_repair_performance.md`。
