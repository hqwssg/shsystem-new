# 实时状态异常注入与恢复测试矩阵

更新时间：2026-09-09

## 1. 目的

本矩阵在正式数据和现场消息接口尚未到位时，验证实时状态进入滚动算法之前的保护行为。测试不判断车辆参数是否真实，而是回答：坏消息会不会进入求解、会不会污染后续可信状态、数据断流时是否停止形成新决策、恢复后是否重新求解，以及不可行结果是否仍被提交。

统一命令：

```powershell
python run_project.py test-realtime-anomalies
```

默认结果目录为 `paper/experiments/realtime_state_anomaly_matrix_current/`。

## 2. 测试范围

| 类别 | 数量 | 主要注入 | 预期保护行为 |
| --- | ---: | --- | --- |
| 字段与时钟 | 16 | 缺字段、错误类型、NaN、负值、越界SOC、过期、未来时钟偏差 | 拒绝消息，不进入可信状态 |
| 顺序与位置 | 6 | 重复、乱序、方向突变、正反向位置异常 | 拒绝单条坏消息且不推进该列车游标，后续合法消息仍可接受 |
| 断流与恢复 | 9 | 无初始数据、全局断流、单列车流缺失/超时、未知列车ID、时钟校正重发 | 扣留新决策、保留最后可信状态，完整新鲜快照到达后标记恢复 |
| 设备状态 | 4 | 重复设备ID、汇总/分设备SOC冲突、负SOC、非法在线状态 | 启动求解前拒绝 |
| 滚动恢复 | 5 | 相同请求、观测变化、首次不可行、连续不可行、设备停运 | 幂等复用、重新求解、有界自动恢复、扣留和人工升级 |

当前共40项。每项同时记录注入方式、预期行为、实际行为、通过状态和结构化证据。

## 3. 实时状态守卫

`realtime_state_guard.py` 提供 `RealtimeStateGuard`。只有同时通过字段、数值、新鲜度、逐列车时间顺序、方向和位置单调性检查的消息，才会推进可信游标。

默认离线测试策略为：

- 最大消息陈旧时间：30秒；
- 最大未来时钟偏差：5秒；
- 断流判定时间：30秒；
- 可选 `expected_train_ids` 用于逐列车完整性检查，避免其他列车持续上报时掩盖单列车断流；集合外未知ID会被拒绝。

这些阈值是软件测试值，不代表现场调度规章。正式接入时必须由接口方确认采样周期、网络延迟、时钟同步方式和允许降级策略。

## 4. 状态与动作

| 状态 | 含义 | 平台动作 |
| --- | --- | --- |
| `no_data_hold` | 尚无任何可信状态 | 等待快照，不形成新自动决策 |
| `incomplete_stream_hold` | 期望列车状态未全部到齐 | 等待完整快照，不使用部分数据下发 |
| `stream_outage_hold` | 全局或某列车状态超过断流阈值 | 保留最后可信状态，扣留新决策 |
| `healthy` | 状态完整且新鲜 | 允许状态进入求解 |
| `recovered` | 断流或不完整后收到完整新鲜状态 | 重新求解，并记录恢复事件 |
| `waiting_for_observation` | 当前运行图不可行且新增发车已扣留 | 等待新观测后重算 |
| `manual_intervention_required` | 连续不可行达到阈值 | 停止自动下发，交由调度员处置 |

相同状态、模板和预算的重复请求由滚动控制器幂等复用；晚点、SOC、设备可用性或临时功率变化会改变观测指纹并触发重新求解。

## 5. 输出

| 文件 | 用途 |
| --- | --- |
| `REALTIME_STATE_ANOMALY_MATRIX_REPORT.md` | 人员阅读的分类、结果和生产动作边界 |
| `realtime_state_anomaly_matrix_summary.json` | 总状态、分类计数、动作策略和边界 |
| `realtime_state_anomaly_matrix_cases.csv` | 40项逐案例预期、实际结果和证据 |
| `realtime_state_anomaly_matrix_failures.json` | 仅保留失败案例，便于CI和问题定位 |

## 6. 当前边界

该矩阵是离线确定性验证，不连接消息中间件、现场主时钟、列控系统或真实储能控制器。它不能替代消息乱序在真实网络中的压力测试、正式列车ID生命周期确认、生产超时SLA、数据库并发故障演练或安全审批，也不表示算法可以直接下发控制指令。
