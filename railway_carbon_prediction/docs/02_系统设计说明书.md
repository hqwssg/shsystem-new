# 碳排放趋势预测模块——系统设计说明书

**版本**：V1.0
**定位**：朔黄铁路大平台中的一个可独立部署、也可嵌入大平台的预测模块
**数据库**：`carbon_emissions`（与大平台同库）
**表前缀**：`prediction_`

---

## 1. 设计目标与边界

### 1.1 目标

1. 对机辆、肃宁、原平三个分公司 2019—2025 年月度碳排放进行异常筛查、因素筛选、趋势预测；
2. 支持每月新增数据接入，新增异常进入人工复核；
3. 支持新增数据少时微调、新增一年以上时全量训练；
4. 预测未来 12 个月并写入数据库，供平台其他模块查询；
5. 预留与大平台集成的 REST 接口、组织映射、鉴权、幂等、异步任务与审计。

### 1.2 不在本期范围

- 平台前端页面开发（仅提供数据契约与接口）；
- 碳核算因子库的制定（沿用企业台账因子与 DQI-MCS 口径）；
- 全国碳市场履约、碳资产管理；
- 不可辨识的政策强度—下降率曲线（表结构/接口预留，v1 仅 BAU）。

## 4. 数据流

### 4.1 历史导入

```
原始 Excel（3 个分公司）
  → 字段标准化（date/year/month/活动量/co2_t/因子）
  → 口径还原（电力因子、供热系数）
  → 缺失推算（周转量、牵引电力、肃宁天然气）
  → 异常处置（2024 机辆天然气）
  → prediction_activity_monthly（长表）
  → prediction_emission_monthly（报表/可比双口径）
  → prediction_policy_factor（外部因子）
  → prediction_dataset_version（版本指纹）
```

### 4.2 训练

```
prediction_emission_monthly + prediction_policy_factor
  → 特征面板（目标、HDD、煤价、煤产量、铁路货运、火电、政策强度）
  → GRA（2019—2024，避免测试泄露）
  → 多折滚动验证（2022/2023/2024）
  → 选 W / 模型 / 隐层
  → 2025 留出测试（只评一次）
  → 2019—2025 重训
  → prediction_model + artifacts/models/{model_id}
```

### 4.3 预测

```
冠军模型 + 最近 W 个月特征
  → 非柴油可比排放预测
  → 柴油模块（台数强度/季节 naive）
  → 总可比排放
  → 热力口径折算 → 报表排放
  → prediction_forecast（BAU）
```

### 4.4 增量接入

```
平台 POST /ingest/monthly
  → 幂等校验 → 写 activity → 重算 emission
  → 单点异常检测
      ├─ 无异常：batch=completed，quality=valid
      └─ 有异常：batch=pending_review，quality=pending
                    → 人工 review
                    → 重算 emission → batch=completed
```

## 5. 关键设计决策

### 5.1 为什么用“可比口径”而不是报表值

电力因子 5 次切换、供热系数 2 次调整，报表值包含“核算规则变化”。直接训练会让模型学到伪趋势。可比口径固定基期因子，只反映活动量/结构变化；预测后再用当年因子折算回报表口径。

### 5.2 为什么柴油独立建模

2025 年柴油 -49% 是已知的机车退役，不是随机波动。把柴油放进 LSTM 会让模型在 2026 年继续按趋势下降或错误反弹。独立模块用“台数×单机强度”把政策事件显式化。

### 5.3 为什么不是所有分公司都用 LSTM

三个分公司样本都只有 84 个月，且肃宁/原平热力占比高、外部因子弱。多折验证结果：

- 机辆：SW-LSTM W=12 最优；
- 肃宁：Ridge W=6 最优（GBM 测试更好但验证稳定性略差）；
- 原平：GBM W=6 最优。

系统按“多折平均 MASE”选冠军，并保留 SW-LSTM 候选；这比“为了算法标签强行 LSTM”更符合小样本实际。

### 5.4 为什么 GRA 结果不能当因果

GRA 衡量趋势相似度，不识别方向、效应大小、贡献率。本期报告中所有表述限定为“关联度排序/趋势相似度”，不使用“贡献率/因果效应”。

## 6. 平台集成设计

### 6.1 组织映射

| 模块 org_id | 平台 dept_id | 名称        |
| --------- | ----------:| --------- |
| JLG       | 3030       | 机辆分公司     |
| SNF       | 3020       | 肃宁分公司     |
| YPF       | 3010       | 原平分公司     |
| SHL       | 3000       | 朔黄铁路（根节点） |

平台可通过 `prediction_org.platform_dept_id` 做映射，不需要改平台组织表。

### 6.2 接口风格

- 统一前缀：`/api/v1/prediction`
- 统一响应：`{code, message, data, trace_id}`
- 鉴权：`X-API-Key`
- 幂等：`idempotency_key`（写入 `prediction_ingest_batch` 唯一键）
- 异步：训练返回 `job_id`，`GET /jobs/{job_id}` 轮询
- 时间：`YYYY-MM` / `YYYY-MM-DD`，数据库 `DATE`
- 错误：400 参数/业务错误；401 鉴权；404 不存在；500 内部错误；503 数据库不可用

### 6.3 与大平台的数据边界

- 本模块**不修改**平台 `sys_*`、`emission_*`、`report_*` 表；
- 只新增 `prediction_*` 表；
- 平台排放核算结果可继续写入 `emission_collection_record`，由 ETL 转成 `prediction_activity_monthly`；
- 预测结果供平台可视化/报表读取 `prediction_forecast` 或 `prediction_v_carbon_monthly`。

### 6.4 部署方式

- 独立进程：`uvicorn carbon_prediction.api:app`；
- 容器化：将 `src/`、`artifacts/`、`.env` 挂载，暴露 8000；
- 平台内嵌：保留 `pipeline.py` 作为服务层，API 可替换为 Spring Cloud/Feign 适配器；
- 定时任务：每月 5 日接入上月数据、异常复核提醒、按需训练、预测刷新。

## 7. 增量训练策略

| 触发   | 条件                         | 动作                                                                 |
| ---- | -------------------------- | ------------------------------------------------------------------ |
| 月度接入 | 新增 1—11 个月                 | `mode=finetune`：LSTM 加载冠军权重，lr=1e-4，少量 epoch；Ridge/GBM 在新数据上 refit |
| 年度全量 | 新增 ≥12 个月                  | `mode=full`：2019—至今全量重训，重新选 W/模型                                   |
| 漂移   | 连续 3 个月实际值超出预测区间，或均值漂移 >2σ | 强制 `full`，并生成对比报告                                                  |
| 口径变更 | 电力因子/供热系数/组织边界变化           | 先更新 `prediction_caliber_rule`/`prediction_emission_factor`，再全量重训   |

**当前实现**：

- `mode=finetune`：加载冠军工件，LSTM 以 `lr=1e-4`、40 epoch 在 2019—as_of 全量历史上再训练；Ridge/GBM 直接 refit；生成 `v1.0-ft` 新版本并提升为冠军。
- `mode=auto`：读取冠军 `train_end`，新增 1—11 个月走 `finetune`，新增 ≥12 个月或尚无冠军走 `full`。
- `mode=full`：完整重跑 GRA、选参、2025 留出评估、2019—as_of 重训。

**冠军替换建议**：当前实现训练完成后直接提升新模型；生产环境建议增加“最近 12 个月回测 MASE 不劣于旧冠军（允许 5% 容差）”的门槛，否则保留旧冠军并记录候选。

## 8. 异常复核流程

```
历史数据：V2 双通道/断点/日历 → 复核级 auto_closed（keep / mark_breakpoint）
                              └→ 关注级 prediction_anomaly_watch（不进队列）
新增数据：稳健 z + 区间
   ├─ |z|≤2.5：正常
   ├─ 2.5<|z|≤3：关注 → watch
   └─ |z|>3：pending → 人工复核
                  │
        ┌─────────┼──────────────┐
        ▼         ▼              ▼
     keep     correct     exclude / mark_breakpoint
        │         │              │
        └─────────┴──────────────┘
                  ▼
        quality_status 更新
        emission 重算
        audit 追加
        batch 完成
```

约束：

- `correct` 必须提供修正值；
- `exclude` 后该点不进入训练，但保留原始值；
- `mark_breakpoint` 保留原值，打 `MANUAL_BREAKPOINT` 标记；
- 复核不可物理覆盖，只能追加审计；
- 复核未完成前，训练查询自动过滤 `quality_status=pending/excluded`。

## 9. 非功能设计

| 项   | 设计                                                     |
| --- | ------------------------------------------------------ |
| 性能  | 单组织训练约 30—45 s（CPU）；预测 3 组织约 2 s；API 同步预测可接受           |
