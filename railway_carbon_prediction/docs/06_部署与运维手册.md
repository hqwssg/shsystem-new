# 碳排放趋势预测模块——部署与运维手册

**适用环境**：Windows / Linux，Python 3.11+，MySQL 8.0+
**默认端口**：8000
**默认库**：`carbon_emissions`

---

## 1. 环境准备

### 1.1 Python

```bash
python --version   # >= 3.11
pip install -r requirements.txt
```

CPU 即可训练；有 GPU 时 PyTorch 会自动使用（本项目默认 CPU）。

### 1.2 MySQL

- 地址：`127.0.0.1:3306`
- 用户：`root`
- 密码：`123456`
- 库：`carbon_emissions`

确认：

```bash
mysql -h 127.0.0.1 -u root -p -e "SELECT VERSION();"
```

生产环境建议新建账号：

```sql
CREATE USER 'carbon_pred'@'%' IDENTIFIED BY '强密码';
GRANT SELECT, INSERT, UPDATE, DELETE ON carbon_emissions.prediction_* TO 'carbon_pred'@'%';
FLUSH PRIVILEGES;
```

> 不要给本模块 `sys_*` 写权限。

### 1.3 配置

```bash
cp .env.example .env
```

修改 `.env`：

```ini
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=123456
DB_NAME=carbon_emissions
API_KEY=请替换为随机长字符串
API_PORT=8000
```

## 2. 初始化

### 2.1 建表 + 种子

```bash
python scripts/init_db.py
```

幂等，可重复执行。会创建 18 张 `prediction_*` 表、1 个视图、组织/品种/因子/情景/政策事件种子。

### 2.2 导入 2019—2025 历史

```bash
python scripts/import_history.py
```

预期输出：

```json
{
  "activity_rows": 2100,
  "emission_rows": 252,
  "quality_issues": 269,
  "external_rows": 2244
}
```

### 2.3 历史异常筛查

```bash
python scripts/anomaly_scan.py
```

预期输出 19 条“异常/严重异常”，自动 `auto_closed`。

### 2.4 训练

```bash
python scripts/train_all.py --orgs JLG,SNF,YPF --as-of 2025-12
```

约 2 min（CPU），生成：

- `artifacts/models/{model_id}/`
- `artifacts/reports/metrics_{org}.json`
- `artifacts/reports/selection_{org}.csv`

### 2.5 预测

```bash
python scripts/forecast.py --horizon 12 --as-of 2025-12
```

写入 `prediction_forecast`，并输出年度汇总。

### 2.6 图表与 Excel

```bash
python scripts/make_report.py
```

生成 `artifacts/reports/*.png` 与 `碳排放预测结果汇总.xlsx`。

### 2.7 一键

```bash
python scripts/run_pipeline.py
```

## 3. 启动 API

```bash
python scripts/run_api.py
```

或：

```bash
uvicorn carbon_prediction.api:app --host 0.0.0.0 --port 8000 --workers 1
```

访问：

- `http://127.0.0.1:8000/health`
- `http://127.0.0.1:8000/docs`

> 注意：DSH Web GUI 在 8940，本模块 API 在 8000，两者互不影响。

### 3.1 systemd（Linux）

```ini
[Unit]
Description=carbon prediction api
After=network.target mysql.service

[Service]
WorkingDirectory=/opt/railway_carbon_prediction
EnvironmentFile=/opt/railway_carbon_prediction/.env
ExecStart=/usr/bin/python3 scripts/run_api.py
Restart=always
User=carbon

[Install]
WantedBy=multi-user.target
```

### 3.2 Windows 服务

可用 NSSM：

```powershell
nssm install CarbonPrediction "C:\Python311\python.exe" "C:\railway_carbon_prediction\scripts\run_api.py"
nssm set CarbonPrediction AppDirectory "C:\railway_carbon_prediction"
nssm start CarbonPrediction
```

## 4. 定时任务建议

| 任务     | 频率     | 命令/接口                           | 说明                      |
| ------ | ------ | ------------------------------- | ----------------------- |
| 月度数据接入 | 每月 5 日 | `POST /ingest/monthly`          | 平台推送上月数据                |
| 异常复核提醒 | 每日     | `GET /anomalies?status=pending` | 超过 3 天未复核升级             |
| 增量训练   | 每月/每季  | `POST /train mode=auto`         | 新增 <12 月微调，≥12 月全量      |
| 预测刷新   | 训练后    | `POST /forecast`                | 写 `prediction_forecast` |
| 报告刷新   | 每月     | `python scripts/make_report.py` | 图表/Excel                |
| 数据备份   | 每日     | `mysqldump`                     | 见第 7 节                  |

### 4.1 自动训练触发逻辑（建议）

```text
每月接入完成后：
  新增月数 = 当前最大 period - 上次训练 train_end
  if 新增月数 >= 12: mode=full
  elif 新增月数 >= 1: mode=finetune
  else: skip
  若连续 3 个月实际值超出预测区间：强制 full
```

当前 `train_all(mode=...)` 已提供入口；生产环境可在平台调度器中实现上述判断。

## 5. 监控

### 5.1 健康检查

```bash
curl http://127.0.0.1:8000/health
```

关注 `status=UP`、`db=carbon_emissions`。

### 5.2 业务监控指标

| 指标     | 来源                                          | 告警建议           |
| ------ | ------------------------------------------- | -------------- |
| 待复核异常数 | `prediction_anomaly status='pending'`       | >10 或最长等待 >3 天 |
| 接入批次失败 | `prediction_ingest_batch status='rejected'` | 立即             |
| 训练任务失败 | `prediction_job status='failed'`            | 立即             |
| 预测缺失   | `prediction_forecast` 未来 12 月不足             | 立即             |
| 模型过期   | `prediction_model.train_end` 超过 13 个月       | 提醒             |
| 数据断档   | `prediction_activity_monthly` 缺月            | 每月检查           |

### 5.3 日志

- API：uvicorn stdout / systemd journal
- 业务审计：`prediction_audit_log`
- 异常审计：`prediction_anomaly_audit`
- 批次：`prediction_ingest_batch`

## 6. 常见问题

### 6.1 `Access denied for user 'root'`

检查 `.env` 密码与 MySQL 实际密码；确认 `127.0.0.1` 而非 `localhost`（socket 差异）。

### 6.2 `Table 'carbon_emissions.prediction_org' doesn't exist`

未执行 `python scripts/init_db.py`，或连接到了错误的库。

### 6.3 训练报 `PermissionError: [WinError 5]`

Windows 受限环境下，`HistGradientBoosting`/多线程会创建管道被拒绝。本项目已改用纯串行 `GradientBoosting`；如仍出现，检查是否自定义了并行模型。

### 6.4 matplotlib 字体缓存告警

```text
Could not save font_manager cache ... Permission denied
```

不影响出图；可设置：

```bash
set MPLCONFIGDIR=%TEMP%\mplconfig
```

### 6.5 中文字体显示方块

安装微软雅黑/SimHei，或在 `reporting.py` 中把字体改为服务器可用字体。

### 6.6 预测结果为空

- 检查 `prediction_model is_champion=1` 是否存在；
- 检查 `artifact_path` 目录是否存在；
- 检查 `prediction_forecast` 是否被清理；
- 调用 `POST /forecast` 重跑。

### 6.7 接入后批次一直 `pending_review`

存在未复核异常。查询：

```sql
SELECT * FROM prediction_anomaly WHERE status='pending' ORDER BY period;
```

逐条复核后批次自动 `completed`。

### 6.8 增量数据把预测“顶”到未来

`forecast_org` 默认取 `MAX(period)` 作为 as_of。若测试/误接入未来月份，先清理：

```sql
DELETE FROM prediction_activity_monthly WHERE period > '2025-12-01' AND batch_id='...';
DELETE FROM prediction_emission_monthly WHERE period > '2025-12-01' AND batch_id='...';
```

再重跑预测。

## 7. 备份与恢复

### 7.1 备份

```bash
mysqldump -h 127.0.0.1 -u root -p carbon_emissions \
  $(mysql -N -e "SELECT GROUP_CONCAT(table_name) FROM information_schema.tables WHERE table_schema='carbon_emissions' AND table_name LIKE 'prediction_%'") \
  > backup_prediction_$(date +%F).sql
```

Windows：

```powershell
mysqldump -h 127.0.0.1 -u root -p123456 carbon_emissions prediction_org prediction_activity_monthly prediction_emission_monthly prediction_anomaly prediction_model prediction_forecast prediction_gra_result prediction_policy_factor prediction_ingest_batch prediction_dataset_version prediction_audit_log prediction_job prediction_anomaly_audit prediction_energy_var prediction_emission_factor prediction_caliber_rule prediction_policy_event prediction_scenario > backup.sql
```

### 7.2 备份模型工件

```bash
tar -czf models_$(date +%F).tar.gz artifacts/models/
```

### 7.3 恢复

1. 建库/建表：`python scripts/init_db.py`
2. 导入 SQL：`mysql ... < backup.sql`
3. 恢复 `artifacts/models/`
4. 校验 `prediction_model.artifact_path` 与目录一致
5. 调用 `/health`、`/forecast` 验证

## 8. 安全

1. 修改默认 `API_KEY`，通过环境变量/密钥管理注入；
2. 生产使用平台网关鉴权，限制 `train` 接口权限；
3. 数据库最小权限；
4. 不把 `.env` 提交到 Git；
5. 对外只暴露 8000，不暴露 MySQL；
6. 审计日志保留 ≥1 年；
7. 预测结果标注“可比/报表口径”和“区间”，避免被当作承诺值。
