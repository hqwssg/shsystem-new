# 碳排放趋势预测模块——数据库设计

**数据库**：`carbon_emissions`（与大平台同库）
**字符集**：`utf8mb4 / utf8mb4_0900_ai_ci`
**引擎**：InnoDB
**表前缀**：`prediction_`
**建表脚本**：`sql/001_schema.sql`；种子：`sql/002_seed.sql`

> 本模块不修改平台已有的 `sys_*`、`emission_*`、`report_*`、`energy_*` 表；仅新增 `prediction_*` 对象。

## 2. 核心表字段

### 2.1 `prediction_org`

| 字段                 | 类型             | 说明                    |
| ------------------ | -------------- | --------------------- |
| org_id             | varchar(16) PK | JLG/SNF/YPF/SHL       |

**映射**：机辆 3030、肃宁 3020、原平 3010、根节点 3000。

### 2.2 `prediction_activity_monthly`

| 字段                    | 类型            | 说明                     |

**var_id 取值**：

| ELEC_TRAC         | 牵引电力（仅机辆；2019—2023 推算，2024 起实测） | MWh   |

### 2.3 `prediction_emission_monthly`

| 字段                    | 类型      | 说明         |
| --------------------- | ------- | ---------- |
| org_id/period/scope   | —       | 唯一键        |
| gas_tco2              | decimal | 天然气排放      |
| gasoline_tco2         | decimal | 汽油排放       |
| diesel_tco2           | decimal | 柴油排放       |
| electricity_tco2      | decimal | 电力排放（报表因子） |
| heat_tco2             | decimal | 热力排放（报表口径） |
| total_reported_tco2   | decimal | 报表总排放      |
| total_comparable_tco2 | decimal | 可比总排放      |
| electricity_factor    | decimal | 当年电力因子     |
| heat_factor           | decimal | 热力因子 0.11  |
| factor_version        | varchar(128) | 本次使用的因子版本组合 |
| heat_area_factor      | decimal | 本次使用的供热面积系数 |
| factor_source         | varchar(255) | 因子来源摘要 |
| factor_snapshot       | json | 本次使用的完整因子快照 |
| is_verified           | tinyint | 年度总量校验     |
| batch_id/data_version | —       | 溯源         |

唯一键：`(org_id, period, scope)`。

**因子与口径规则版本字段**：

| 表 | 新增字段 | 说明 |
| --- | --- | --- |
| `prediction_emission_factor` | `factor_version` varchar(64) | 因子版本，如 `EF-ELEC-2025`；同一 `var_id` 生效期不得重叠 |
| `prediction_caliber_rule` | `rule_version` varchar(64) | 规则版本，如 `CAL-SNF-2025`；同组织同类型生效期不得重叠 |

因子解析顺序：`var_id + effective_from/effective_to`；供热面积系数按 `org_id` 专属优先于 `ALL`，再按生效期。计算完成后把实际使用的因子写入 `factor_snapshot`，保证历史可追溯。

## 4. 数据血缘与状态码

### 4.1 `source_status`

| 值         | 含义            |
| --------- | ------------- |
| 原始        | 台账原值          |
| 推算-电量系数法  | 周转量缺失，按电量强度推算 |
| 推算-辅占比重构  | 牵引/辅助拆分       |
| 推算-供暖度日分摊 | 年总量按 HDD 分摊   |
| 异常剔除-同期补全 | 2024 机辆天然气    |
| 口径还原      | 2025 供热系数还原   |
| 无此项       | 原平无天然气        |
| 人工修正      | 复核 correct    |

### 4.2 `quality_status`

| 值        | 含义  | 训练是否使用 |
| -------- | --- | ------ |
| valid    | 有效  | 是      |
| pending  | 待复核 | 否      |
| excluded | 已排除 | 否      |

### 4.3 `data_flag`

`GAS_2024_ANOMALY`、`CALIBER_CHANGE_2025`、`LEVEL_SHIFT_2024`、`LOCO_RETIREMENT_2025`、`ESTIMATED_2019_2020`、`ANOMALY_BREAKPOINT`、`MANUAL_BREAKPOINT`。

## 6. 初始化与迁移

```bash
python scripts/init_db.py
```

脚本幂等：`CREATE TABLE IF NOT EXISTS`、`INSERT ... ON DUPLICATE KEY UPDATE`、视图先 `DROP VIEW IF EXISTS`。

**与平台集成注意**：

1. 平台已有 `sys_dept` 组织树，本模块通过 `platform_dept_id` 映射，不复制组织权限；
2. 平台已有 `emission_collection_record`，ETL 时应按 `(org_id, period, var_id)` 汇总后写入 `prediction_activity_monthly`；
3. 若平台后续统一排放因子，`prediction_emission_factor` 可由平台同步，本模块只读；
4. 生产环境建议给本模块单独数据库账号，授予 `prediction_*` 表读写权限，不授予 `sys_*` 写权限。

## 7. 备份与恢复

- 每日全量：`mysqldump carbon_emissions prediction_*`
- 每周备份模型工件目录 `artifacts/models/`
- 恢复顺序：表结构 → 种子 → 历史导入 → 模型工件 → 预测结果
- 模型工件与 `prediction_model.artifact_path` 必须一致，否则预测会回退重训。
