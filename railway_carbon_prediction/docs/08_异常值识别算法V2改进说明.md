## 1. 结论

第 13.2 节的 6 条改进建议**均可落地**。本次已完成 6 条，并将主检测算法从 V1 切换为 V2：

| #   | 改进建议                         | 是否可做          | 本次落地                                                                                | 结果                                                                        |
| ---:| ---------------------------- | ------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| 1   | 用复核结果构造标签，校准阈值/contamination | 可做，但当前只有弱标签   | 新增 `prediction_anomaly_calibration`，用 V1 结果做弱标签，扫描 q=0.90—0.99 的 P/R/F1             | 单次 12 行校准；JLG 电力 q=0.98、天然气 q=0.97 的 F1=1.0，但样本仅 2—3 个正例，不能当 ground truth |
| 2   | raw/STL 残差两棵独立森林，双通道一致升级     | 可做            | `anomaly_v2` 分别训练 raw 与 resid 两棵森林，`channels` 记录 raw/resid/joint 组合                 | 双通道一致的点升级；单通道点进监控或降级                                                      |
| 3   | PELT/CUSUM 做 C3 断点           | 可做（CUSUM 部分）  | 实现 CUSUM 思想 + 池化统计量断点扫描，三判据：统计量≥3、位移≥25%、后段 CV≤前段×1.5                               | 柴油 2024-10：stat=9.19、位移 -47.74%、CV 比 0.87，正确识别                            |
| 4   | 节假日/疫情/检修哑变量                 | 春节/疫情可做；检修缺数据 | `prediction_calendar_event` 登记 8 个春节 + 1 个疫情；检修表已预留                                 | 日历可解释的短段异常从复核队列转入监控                                                       |
| 5   | 电力/热力/柴油/产量多变量联合检测           | 可做            | 对 ELEC/DIESEL/GAS/GASOLINE/TURNOVER 做联合孤立森林                                         | 联合只做佐证，不单独产出异常，避免小量级品种被淹没                                                 |
| 6   | “关注”级独立监控表                   | 可做            | 新增 `prediction_anomaly_watch`，API 增加 `/anomalies/watch`、`/anomalies/quality-report` | 143 条关注级进入监控，不进复核队列                                                       |

**最终分流**：

- 复核级异常：**8 条**（V1 为 19 条）；
- 关注级监控：**143 条**；
- 弱标签校准：单次 **12 行**；
- V1 历史结果：**19 条**，备份在 `prediction_anomaly_v1`。

> 复核级从 19 条降到 8 条，不是“漏检”，而是把 COVID/春节可解释的短段、热力确定性序列、低物质性品种（汽油/天然气小台阶）分流到监控或规则登记，减少人工队列噪声。

上传的《异常值识别算法设计与检测结果说明.md》**有较高借鉴价值**，本次吸收了 5 个设计思想，但没有照搬其全部实现。

### 2.1 已借鉴

| 上传文档思想                           | 本次落地                                          | 价值                  |
| -------------------------------- | --------------------------------------------- | ------------------- |
| 逐品种 STL 残差 + MAD 修正 z 作为主力判据     | V2 保留逐品种 MAD z，作为 C1/C2/C4 的主要证据              | 解决联合森林对小量级品种不敏感     |
| 双通道孤立森林（raw vs resid），按“双通道一致”升级 | V2 训练两棵独立森林，`channels=raw+resid`              | 区分“季节可解释”和“残差形态异常”  |

| 规则优先级 / fail-safe                | V2 先 C3 断点，再 C4 季节，再 C1/C2，未定类进监控/复核          | 避免规则乱序              |

| 上传文档内容                        | 本次处理                             | 原因                                        |

## 3. V2 算法结构

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 证据层                                                   │
│    A. 逐品种 STL 残差 + MAD z（主力）                        │
│    B. raw 森林 + resid 森林（双通道）                        │
│    C. CUSUM/池化断点（月度，三判据）                          │
│    D. 多变量联合森林（仅佐证）                                │
│    E. 日历哑变量（春节/疫情/检修）                            │
│    F. 确定性序列 HEAT：跳过统计，规则登记                      │
├─────────────────────────────────────────────────────────────┤
│ 2. 分类层                                                   │
│    C3 断点 → C4 季节 → C1 单点 → C2 连续 → UNDETERMINED     │
│    日历可解释的短段 C1/C2 → 监控                              │
│    连续段≥6 → 不判 C4                                        │
├─────────────────────────────────────────────────────────────┤
│ 3. 分流层                                                   │
│    异常/严重异常 → prediction_anomaly（复核队列）              │
│    关注级 → prediction_anomaly_watch（监控）                  │
│    热力规则事件 → prediction_anomaly（C3/rule）               │
└─────────────────────────────────────────────────────────────┘
```

### 3.1 双通道特征

**raw 通道**（10 维）：

`value, mom, yoy, roll_mean3, roll_std3, month_sin, month_cos, CAL_SPRING_FESTIVAL, CAL_COVID, CAL_MAINTENANCE`

**resid 通道**（9 维）：

`resid, resid_z, abs_resid_z, resid_roll_std3, month_sin, month_cos, CAL_SPRING_FESTIVAL, CAL_COVID, CAL_MAINTENANCE`

两棵森林均为：

```python
IsolationForest(
    n_estimators=200,
    max_samples="auto",
    contamination=0.05,
    random_state=20260928,
    n_jobs=1,
)
```

- `raw_score = -score_samples(raw_X)`
- `resid_score = -score_samples(resid_X)`
- 分位阈值：`FOREST_QUANTILE = 0.95`，即各通道前 5% 视为触发；
- `both = raw_flag and resid_flag`；
- `either = raw_flag or resid_flag`；
- `joint` 只做佐证，**不单独产出异常**。

### 3.2 MAD 修正 z

```
med = median(resid)
MAD = median(|resid − med|)
σ = 1.4826 × MAD
z = (resid − med) / σ
```

- `|z| > 3` 进入候选；
- `|z| > 5` 升级为严重异常；
- 连续段长、同月同向复现作为 C1/C2/C4 的辅助证据。

### 3.3 月度断点（CUSUM/池化）

对每个候选切点 `t`（左右各至少 6 个月）：

```
pooled_std = sqrt[((nL−1)·varL + (nR−1)·varR) / (n−2)]
stat = |meanR − meanL| / pooled_std × sqrt(nL·nR/n)
shift_pct = (meanR − meanL) / |meanL| × 100
CV_L = stdL / |meanL|
CV_R = stdR / |meanR|
```

三判据同时满足才判断点：

1. `stat ≥ 3.0`；
2. `|shift_pct| ≥ 25%`；
3. `CV_R ≤ CV_L × 1.5`，或断点后均值≈0（归零/停用）。

断点后 3 个月为过渡窗，只有窗内点才标 C3。柴油 2024-10 实测：

| 指标          | 值          |
| ----------- | ----------:|
| stat        | 9.1938     |
| shift_pct   | -47.744%   |
| CV_R / CV_L | 0.8734     |
| 判定          | C3 persist |

> 实现是 CUSUM 思想 + 池化统计量，不是 `ruptures` 的 PELT；原因是当前环境未安装 `ruptures`，且月度样本只有 84 个，池化统计量更稳定、可解释。

### 3.4 日历哑变量

`prediction_calendar_event` 当前登记：

- 2019—2026 年 8 个春节假期；
- 2020-01—2020-04 疫情初期；
- 检修事件：表结构已就绪，**尚无企业检修计划数据**，`CAL_MAINTENANCE` 暂为 0。

作用：

- 作为森林特征，降低“春节/疫情月份”被误判为数据错误；
- 对日历可解释的 C1/C2 短段，**不进复核队列**，转 `prediction_anomaly_watch`；
- 在 evidence 中保留 `context_flags`，审计可追溯。

### 3.5 多变量联合

联合变量：`ELEC_TOTAL, DIESEL, GAS, GASOLINE, TURNOVER`。

- 标准化后加月份正余弦，训练孤立森林；
- `joint_flag = 联合分位 ≥ 95%`；
- 联合只用于：
  - 升级置信度：`both` 或 `joint + 单通道` → 异常；
  - 解释跨品种同步变化；
- **联合不单独产出异常**，避免天然气/汽油等小量级品种被电力淹没。

### 3.6 确定性热力豁免与规则登记

V2 对 `HEAT` 完全跳过统计检测，理由与上传文档一致：热力由供热面积/档位规则解释，零值月与档位跳变会被统计法大量误判。

改为规则登记 3 个已知事件：

| 组织  | 期间      | 事件        | 年热力变化              |
| --- | ------- | --------- | ------------------:|
| 机辆  | 2023-01 | 供热面积/档位调整 | 72,809→88,618 GJ   |
| 肃宁  | 2023-11 | 供热面积调整    | 49,687→63,618 GJ   |
| 原平  | 2021-12 | 供热面积调整    | 142,318→159,377 GJ |

这些事件以 `channels=rule`、`category=C3` 进入复核表，`final_disposition=mark_breakpoint`，不参与统计打分。

### 3.7 分类与分流

| 条件           | 类别                    | 分流            |
| ------------ | --------------------- | ------------- |
| 断点窗内         | C3（zero_exit/persist） | 复核            |
| 日历可解释短段      | C1/C2                 | 监控            |
| 连续段≥6        | C2（质量台阶）              | 复核（若严重）或监控    |
| 单点 z>3       | C1                    | 复核（若双通道/联合支持） |
| 连续 2—5 点 z>3 | C2                    | 复核/监控         |
| 仅联合触发        | —                     | 不产出           |
| 未定类且严重       | UNDETERMINED          | 复核            |
| 未定类且非严重      | UNDETERMINED          | 监控            |

**复核准入**（`_is_reviewable`）：

- C3、规则登记事件：进复核；
- 天然气：仅“严重 + 连续≥6 月”的台阶进复核；
- 汽油：只进监控（量级 0.035%）；
- 日历可解释且连续段<6：只进监控；
- 其他：严重异常，或双通道且 `|z|≥5`，才进复核。

## 5. 处置流程

### 5.1 历史数据

- V2 复核级 8 条全部 `auto_closed`；
- C3/C2 → `mark_breakpoint`；C1 → `keep`；
- 原值不删除、不自动修正；
- V1 19 条保留在 `prediction_anomaly_v1`，可对照。

### 5.2 新增数据

```
新增记录 → 写入 activity → 重算 emission
  → detect_new_point_v2（同月稳健 z）
      ├─ |z|≤2.5：正常
      ├─ 2.5<|z|≤3 或 outside：关注 → prediction_anomaly_watch
      └─ |z|>3 或 outside：异常/严重 → prediction_anomaly(pending)
            → 人工复核 keep/correct/exclude/mark_breakpoint
            → 重算 emission + 审计
```

新增异常不再进入“关注”表；关注表只承载监控级。`review_anomaly` 逻辑保持不变。

### 5.3 API

| 方法   | 路径                                            | 用途         |
| ---- | --------------------------------------------- | ---------- |
| POST | `/api/v1/prediction/anomalies/scan`           | 运行 V2 历史筛查 |

## 7. 局限与后续

1. **弱标签不是 ground truth**：当前只有 V1 的 19 条规则/自动处置结果，正例 2—3 个/序列，校准 F1 容易过拟合；需要真实人工复核积累后重新校准。
