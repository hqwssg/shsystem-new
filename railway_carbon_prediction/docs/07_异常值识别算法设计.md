## 1. 概述

### 1.1 目标

在碳排放月度数据进入 GRA 与预测模型之前，识别以下三类问题：

1. **数据错误**：抄表中断后补录错误、单位误填、重复上报、系统默认值；
2. **计量/口径异常**：连续多点漂移、计量通道异常、核算口径切换；
3. **真实业务跃变**：疫情/春节需求冲击、供暖面积变化、内燃机车退役、新线开通等。

异常识别不是“自动删除异常点”，而是回答三个问题：

- 这个点是否偏离历史规律？
- 偏离是“数据错误”还是“真实业务事件”？
- 应该保留、修正、排除，还是标记为结构断点？

### 1.2 设计原则

| 原则          | 说明                          |
| ----------- | --------------------------- |
| 不自动删除       | 历史数据已核实，删除可能破坏真实趋势；只做保留/标记  |
| 先季节调整       | 用 STL 残差降低供暖季、春运等正常峰谷的误报    |
| 区分孤立尖峰与水平位移 | C1 单点错误 vs C3 真实结构断点，处置完全不同 |
| 分级处置        | 历史自动闭环；新增数据必须人工复核           |
| 全程留痕        | 异常得分、证据、处置、复核人、时间全部入库       |
| 保守优先        | 无法判定的异常保留原值，不轻易修正           |

### 1.3 与主方案的关系

主方案的三级链路是“孤立森林异常检测（一级）→ 灰色关联筛选（二级）→ 滑动窗口 LSTM（三级）”。本文只展开第一级，说明：

- 异常如何被识别；
- 异常如何被分类；
- 异常如何被处置；
- 处置结果如何影响后续 GRA/训练/预测。

## 3. 算法总体流程

```
原始月度序列
   │
   ▼
STL 分解（period=12, robust=True）
   │  得到 trend / seasonal / resid
   ▼
特征构造（9 维）
   │  value, resid, resid_z, mom, yoy,
   │  roll_mean3, roll_std3, month_sin, month_cos
   ▼
StandardScaler 标准化
   │
   ▼
IsolationForest（200 棵树，contamination=0.03）
   │
   ├─ score_samples → s = -score_samples
   ├─ decision_function → <0 判异常
   └─ 分数分位 → percentile
   ▼
异常分级（正常/关注/异常/严重异常）
   │
   ▼
C1—C4 规则分类
   │
   ├─ 历史批量：auto_closed（keep / mark_breakpoint）
   └─ 新增单点：pending → 人工复核
```

## 4. 特征工程

### 4.1 STL 分解

对每个组织×品种序列做稳健 STL：

```
y_t = T_t + S_t + R_t
```

- `T_t`：趋势项；
- `S_t`：季节项（period=12）；
- `R_t`：残差项，作为“剔除季节后的异常形态”主依据。

STL 使用 `robust=True`，降低历史极端值对趋势/季节项的拉扯。

### 4.2 特征表

| 特征         | 含义         | 作用                 |
| ---------- | ---------- | ------------------ |
| value      | 原始值        | 捕捉量级异常（单位误填、数量级跳变） |
| resid      | STL 残差     | 捕捉剔除季节后的形态异常       |
| resid_z    | 残差 / 残差标准差 | 统一量纲，突出偏离程度        |
| mom        | 环比变化率      | 捕捉突变               |
| yoy        | 同比变化率      | 捕捉年度水平变化           |
| roll_mean3 | 3 期滚动均值    | 局部水平               |
| roll_std3  | 3 期滚动标准差   | 局部波动               |
| month_sin  | 月份正弦       | 保留季节相位             |
| month_cos  | 月份余弦       | 保留季节相位             |

> 这 9 维特征同时包含“原始量级”和“STL 残差形态”，相当于把主方案中的 raw 通道与 stl_residual 通道在特征层融合。实现上没有分别训练两棵孤立森林，而是在同一特征矩阵中同时提供两类信息；这是工程上的简化，效果上仍能同时识别量级异常与形态异常。

### 4.3 标准化

使用 `StandardScaler` 对 9 维特征做 Z-score：

```
z_j = (x_j − μ_j) / σ_j
```

标准化只在当前序列内进行（无监督检测，不涉及预测任务的数据泄露）。

## 5. 孤立森林模型

### 5.1 基本原理

孤立森林通过随机特征、随机分割点构造二叉树。异常点远离密集区域，通常在很少的分割次数内被孤立，路径长度较短；正常点需要更多分割。

样本 x 在单棵树上的路径长度为 h(x)，T 棵树的平均路径长度：

```
E(h(x)) = (1/T) Σ h_t(x)
```

归一化基准：

```
c(n) = 2H(n−1) − 2(n−1)/n
H(i) ≈ ln(i) + γ,  γ = 0.5772156649
```

异常得分：

```
s(x, n) = 2^(−E(h(x)) / c(n))
```

`s → 1` 表示异常可能性高，`s ≈ 0.5` 表示与正常样本无明显区别。

### 5.2 实现口径

本系统使用 scikit-learn 的 `IsolationForest`：

```python
s = -model.score_samples(X)      # 排序、分级统一使用
is_anomaly = model.decision_function(X) < 0
```

注意：

- 不使用 `predict()` 的 ±1 反推得分；
- `s` 越大越异常；
- `score_percentile = rank(s, pct=True) × 100`；
- 由于 `contamination=0.03`，`decision_function<0` 的点约占 3%，但分级还会结合分位数，因此“严重异常”可能多于 3%。

### 5.3 参数

| 参数            | 取值               | 说明          |
| ------------- | ----------------:| ----------- |
| n_estimators  | 200              | 树数量         |
| max_samples   | auto（min(256,N)） | 子采样规模       |
| contamination | 0.03             | 预期异常比例      |
| random_state  | 20260928         | 全局可复现种子     |
| n_jobs        | 1                | 避免受限环境线程池问题 |
| STL period    | 12               | 月度季节周期      |
| STL robust    | True             | 稳健分解        |
| 最小序列长度        | 24               | 少于 24 点跳过   |

## 6. 异常分级

### 6.1 分级规则

| 等级   | 判据                             | 处置          |
| ---- | ------------------------------ | ----------- |
| 正常   | `s < 0.55` 且 `decision ≥ 0`    | 不处理         |
| 关注   | `0.55 ≤ s < 0.65`，或仅单通道异常      | 在线监控，不落库    |
| 异常   | `s ≥ 0.65` 且 `decision < 0`    | 进入异常清单      |
| 严重异常 | `s ≥ 0.75` 或 `percentile ≥ 99` | 进入异常清单，优先复核 |

> 历史批量筛查只固化“异常/严重异常”；“关注”级不落库，避免 84 个点上产生 100+ 条噪声。新增数据仍会按“异常/严重异常”进入 pending。

### 6.2 为什么用分位数

不同序列的得分分布不同。仅用绝对阈值会让高波动序列漏报、低波动序列过报。因此同时使用：

- 绝对得分 `s`；
- 序列内分位 `percentile`；
- `decision_function` 的二值边界。

三者结合，兼顾“绝对偏离”和“相对稀有”。

## 7. C1—C4 分类规则

### 7.1 类别定义

| 类别  | 含义     | 典型原因              | 处置              |
| --- | ------ | ----------------- | --------------- |
| C1  | 数据错误   | 抄表错误、单位误填、重复上报    | 保留/修正（历史已核实则保留） |
| C2  | 计量异常   | 电表/轨道衡故障、连续漂移     | 标记断点/整段不可信      |
| C3  | 真实业务跃变 | 疫情、供暖面积变化、机车退役、新线 | 保留并标记结构断点       |
| C4  | 季节峰谷   | 供暖季、春运、暑运         | 保留，不处理          |

### 7.2 判定顺序

实现中按以下优先级判定（先命中先返回）：

```
C4（供暖月且 |resid| < 2σ）
  > C3（前后 3 期均值位移 > 2σ 且 > 15%）
    > C1（单点尖峰，前后方向相反且都 > 2σ）
      > C2（连续 3 点同向漂移）
        > UNDETERMINED（统计异常，证据不足）
```

### 7.3 公式

**C4 季节峰谷**

```
month ∈ 供暖月 且 |R_t| < 2σ_R
```

**C3 水平位移**

```
before = mean(y[i−3:i])
after  = mean(y[i:i+3])
|after − before| > 2σ_R
且 |after − before| > 0.15 × max(|before|, ε)
```

**C1 孤立尖峰**

```
d1 = y[i] − y[i−1]
d2 = y[i+1] − y[i]
sign(d1) ≠ sign(d2)
且 |d1| > 2σ_R 且 |d2| > 2σ_R
```

**C2 连续漂移**

```
最近 3 个点的一阶差分绝对值均 > σ_R
```

### 7.4 置信度

| 类别           | 置信度  | 说明        |
| ------------ | ----:| --------- |
| C1           | 0.78 | 尖峰形态明确    |
| C3           | 0.72 | 水平位移明确    |
| C4           | 0.65 | 季节性解释     |
| C2           | 0.60 | 连续漂移      |
| UNDETERMINED | 0.45 | 证据不足，倾向保留 |

> 置信度只用于排序和提示，不替代人工判断。

## 8. 新增数据单点检测

历史批量用孤立森林；新增一个月的数据只有一个点，无法重新训练森林，因此采用**稳健单点打分**：

### 8.1 稳健 z 分数

取同月历史（至少 3 年）作为基准；不足 3 年则用最近 24 个月：

```
med = median(base)
MAD = median(|base − med|)
σ = 1.4826 × MAD
z = (value − med) / σ
```

同时检查是否超出历史区间：

```
outside = value > max(history) × 1.2
       或 value < max(0, min(history) × 0.8)
```

### 8.2 判定

```
|z| > 3 或 outside → 异常
```

- `|z| > 5` → 严重异常；
- 否则 → 异常；
- 得分 `s = min(1, |z| / 10)`，仅用于排序；
- 类别先置 `UNDETERMINED`，等待人工复核。

### 8.3 示例

新增肃宁 2026-02 电力 999,999 MWh：

```
历史同月中位数 = 4,104.45
稳健 z = 1,199.21
超出历史区间 = True
→ 严重异常，pending
```

复核为 `correct`、修正值 3,000 MWh 后，系统重算该月排放并写审计。

## 9. 处置与复核流程

### 9.1 历史数据：自动闭环

历史数据已核实、台账不可追溯，系统不做删除，只做两类处置：

| 处置              | 适用                          | 结果                             |
| --------------- | --------------------------- | ------------------------------ |
| keep            | C1/C4/UNDETERMINED，或无法证明是错误 | 保留原值，`status=auto_closed`      |
| mark_breakpoint | C3/C2，真实水平位移或计量漂移           | 保留原值，写 `ANOMALY_BREAKPOINT` 标记 |

历史异常不进入人工待办，但全部写入 `prediction_anomaly`，`reviewer=system`，`reviewed_at` 为筛查时间。

### 9.2 新增数据：人工复核

新增数据命中异常后：

1. 活动数据写入 `prediction_activity_monthly`，`quality_status=pending`；
2. 异常写入 `prediction_anomaly`，`status=pending`；
3. 批次 `prediction_ingest_batch.status=pending_review`；
4. 训练查询自动排除 `pending/excluded`；
5. 复核后重算该月排放，批次完成。

### 9.3 复核动作

| 动作              | 含义        | 对活动数据                                     | 对训练         |
| --------------- | --------- | ----------------------------------------- | ----------- |
| keep            | 保留原值      | quality=valid                             | 进入训练        |
| correct         | 修正为指定值    | 更新 value/reported_value，quality=valid     | 进入训练        |
| exclude         | 排除该点      | quality=excluded                          | 不进入训练       |
| mark_breakpoint | 保留原值，标记断点 | quality=valid，data_flag=MANUAL_BREAKPOINT | 进入训练，作为断点解释 |

### 9.4 审计与重算

- `prediction_anomaly_audit` 追加：动作、修正前值、修正后值、复核人、理由、时间；
- 重算该月 `prediction_emission_monthly`；
- 批次下无 pending 异常时，`prediction_ingest_batch.status=completed`；
- 所有操作写 `prediction_audit_log`。

### 9.5 接口

| 方法   | 路径                                            | 用途        |
| ---- | --------------------------------------------- | --------- |
| POST | `/api/v1/prediction/ingest/monthly`           | 新增数据，自动检测 |
| GET  | `/api/v1/prediction/anomalies?status=pending` | 待复核列表     |
| POST | `/api/v1/prediction/anomalies/{id}/review`    | 复核        |
| POST | `/api/v1/prediction/anomalies/scan`           | 历史批量筛查    |

复核请求示例：

```json
{
  "action": "correct",
  "correction_value": 3000,
  "reviewer": "张三",
  "note": "与供电段台账核对，正确值为 3000 MWh"
}
```

## 11. 异常结果如何进入模型

### 11.1 训练数据过滤

```sql
WHERE quality_status = 'valid'
```

`pending`、`excluded` 不进入训练。历史异常均为 `valid`，只通过 `data_flag` 标记断点，不删除。

### 11.2 结构断点的处理

| 断点               | 模型处理                    |
| ---------------- | ----------------------- |
| 2020-02 电力需求冲击   | 保留在历史窗口，作为真实水平位移        |
| 2024-10 柴油退役     | 柴油独立模块按台数预测，不进入 LSTM 目标 |
| 2025 供热系数调整      | 可比口径还原，报表口径单独折算         |
| 2022—2025 电力因子切换 | 固定 0.5306 构造可比目标        |
| 天然气小台阶           | 气量占比极低，不单独建模            |

### 11.3 异常与 GRA

异常点不删除，但会在 `prediction_anomaly` 中保留证据。GRA 使用 2019—2025 全序列，结构断点可能降低关联度；因此 GRA 结论偏保守，不把弱关联解释为“无影响”。

## 13. 局限与改进方向

### 13.1 局限

1. **无标签**：没有人工标注的“真异常/假异常”，无法计算 precision/recall；当前依赖保守规则与人工复核。
2. **单序列建模**：每个组织×品种独立建树，未做跨品种联合异常（如“电量正常但热力异常”的组合异常）。
3. **分类规则启发式**：C1—C4 基于 3 期均值/2σ/方向，未使用 PELT/CUSUM 正式断点检验。
4. **固定 contamination**：0.03 是经验值，未按序列自适应。
5. **参考值是全序列中位数**：用于快速判断量级，不是局部期望；局部证据看 `evidence` 文本。
6. **历史自动处置**：C1 历史点保留原值，可能漏掉真实录入错误；这是“不破坏已核实台账”的取舍。

### 13.2 改进建议

1. 用复核结果构造标签，校准阈值与 contamination；
2. 增加 raw 通道与 STL 残差通道两棵独立森林，按“双通道一致”升级；
3. 引入 PELT/CUSUM 做 C3 断点检验，替代 3 期均值；
4. 增加节假日/疫情/检修哑变量，降低 C3 误报；
5. 对关键品种做多变量联合检测（电力、热力、柴油、产量）；
6. 将“关注”级写入独立监控表，不进入复核队列，但用于月度数据质量报告。

## 14. 结论

本算法在 84 个月×3 组织×5 序列上运行，固化 19 条“异常/严重异常”：

- 11 条 C3 结构断点，全部保留原值并标记；
- 4 条 C1 单点尖峰，历史已核实，保留；
- 1 条 C2 连续漂移，标记断点；
- 1 条 C4 季节峰谷，保留；
- 2 条 UNDETERMINED，保守保留。

没有删除任何历史值，没有自动修正；所有处置可追溯。新增数据则走 `pending → 人工复核 → 重算/审计` 闭环。该设计满足“历史数据自动处理、新增异常人工决策”的业务要求，也为后续模型提供了可解释的结构断点标记。
