# 碳排放趋势预测模块——接口文档

**Base URL**：`http://{host}:8000`
**API 前缀**：`/api/v1/prediction`
**在线文档**：`/docs`（Swagger UI）、`/redoc`
**鉴权**：请求头 `X-API-Key: dev-key`（生产环境通过 `API_KEY` 环境变量覆盖）
**健康检查**：`GET /health` 不需要鉴权

---

## 1. 通用约定

### 1.1 统一响应

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "trace_id": "8bb950a3ef974e90"
}
```

| code | 含义         |
| ----:| ---------- |
| 0    | 成功         |
| 400  | 参数/业务校验失败  |
| 401  | API Key 无效 |
| 404  | 资源不存在      |
| 500  | 服务内部错误     |
| 503  | 数据库不可用     |

### 1.2 时间与单位

- 月份：`YYYY-MM`；数据库存每月 1 日。
- 时间戳：ISO 8601。
- 排放：`tCO2e`；电力：`MWh`；热力：`GJ`；天然气：`万m³`；汽油/柴油：`t`；周转量：`百万吨公里`。
- 所有活动量不得为负。

### 1.3 幂等

`POST /ingest/monthly` 支持 `idempotency_key`。同一 key 重复提交返回首次批次，不重复写入。

### 1.4 异步任务

训练类接口返回 `job_id`，通过 `GET /jobs/{job_id}` 轮询；状态：`queued/running/succeeded/failed`。

### 2.6 比对能耗值

```http
GET /api/platform/energy/compare?orgId=JLG&period=2025-12&varId=ELEC_TOTAL&value=148764.116
```

参数：

| 参数       | 必填  | 说明          |
| -------- | --- | ----------- |
| `orgId`  | 是   | JLG/SNF/YPF |
| `period` | 是   | `YYYY-MM`   |
| `varId`  | 是   | 能耗品种编码      |
| `value`  | 是   | 待比较数值       |

返回：

```json
{
  "code": 0,
  "data": {
    "result": 1,
    "exists": true,
    "equal": true,
    "orgId": "JLG",
    "periodLabel": "2025-12",
    "varId": "ELEC_TOTAL",
    "inputValue": 148764.116,
    "storedValue": 148764.116,
    "message": "值相等"
  }
}
```

`result` 含义：

| 值   | 含义                      |
| ---:| ----------------------- |
| `1` | 记录存在，且提交值与库中 `value` 相等 |
| `0` | 记录存在，但值不相等              |
| `2` | 指定分公司、月份、能耗品类记录不存在      |

比较采用 `BigDecimal.compareTo`，`1000` 与 `1000.000000` 视为相等。`items` 中的 `value` 与接口比较的字段一致，不使用 `reported_value`。

## 6. 月度增量接入

### 6.1 提交

```http
POST /api/v1/prediction/ingest/monthly
Content-Type: application/json

{
  "idempotency_key": "JLG-2026-01-001",
  "operator": "platform",
  "run_anomaly": true,
  "factor_version": "EF-GAS-2019|EF-GASOLINE-2019|EF-DIESEL-2019|EF-ELEC-2026|EF-HEAT-2019|CAL-JLG-2019",
  "override": false,
  "override_reason": null,
  "records": [
    {"org_id": "JLG", "period": "2026-01", "var_id": "ELEC_TOTAL", "value": 150000, "unit": "MWh"},
    {"org_id": "JLG", "period": "2026-01", "var_id": "ELEC_TRAC", "value": 149000, "unit": "MWh"},
    {"org_id": "JLG", "period": "2026-01", "var_id": "ELEC_AUX", "value": 1000, "unit": "MWh"},
    {"org_id": "JLG", "period": "2026-01", "var_id": "DIESEL", "value": 600, "unit": "吨"},
    {"org_id": "JLG", "period": "2026-01", "var_id": "HEAT", "value": 16920, "unit": "GJ"}
  ]
}
```

- **机辆后续不再自动拆分**：必须同时提供 `ELEC_TOTAL/ELEC_TRAC/ELEC_AUX`，且校验 `总电力 = 牵引 + 辅助`；缺项返回 422；
- 肃宁/原平无牵引电力：只传 `ELEC_TOTAL` 时自动补 `ELEC_AUX = ELEC_TOTAL`，传 `ELEC_TRAC` 会被拒绝；
- 热力可传 `value`（物理/可比）和 `reported_value`（报表）；只传 `value` 时两者相同；
- 系统自动重算 `prediction_emission_monthly`；
- **活动数据不携带排放因子**，系统按 `org_id + period + var_id` 解析当前生效因子；
- `factor_version` 可选。传了则校验，和当前解析版本不一致返回 `409`，不会静默改算；
- 因子缺失返回 `422`，不会先写活动数据；因子冲突返回 `409`；
- **同月已入库默认拒绝**：返回 `409`，提示已有批次；如确需覆盖，传 `override=true` 且 `override_reason` 必填；
- 覆盖时先写入 `prediction_ingest_audit`：旧活动值、旧排放值、旧异常状态，并把旧 `pending` 异常标记为 `rejected`；
- **同一 idempotency_key 必须对应同一请求体**：请求体 hash 不一致返回 `409`，不会静默返回旧批次。

### 6.2 响应

无异常：

```json
{"code": 0, "message": "数据已接收", "data": {"batch_id": "ING-...", "status": "completed", "row_count": 3, "anomaly_count": 0}}
```

有异常：

```json
{
  "code": 0,
  "message": "数据已接收，存在待复核异常",

    "batch_id": "ING-...",
```

### 6.3 碳核算月度快照

仍使用 `POST /api/v1/prediction/ingest/monthly` 和现有 `X-API-Key`。没有 `source_snapshot` 的请求沿用原有接入规则。每份核算快照包含一家公司、一个月份和一组品种。

| 字段 | 含义 |
|---|---|
| `idempotency_key` | `carbon-month-<version>`。同版本重试使用原请求体 |
| `source_snapshot.version` | 碳核算发送记录的单调递增 ID |
| `source_snapshot.org_id`、`period` | `JLG`、`SNF` 或 `YPF`，月份格式为 `YYYY-MM` |
| `source_snapshot.operation_type` | `1` 凌晨统计，已有同月记录则跳过。 `2` 基准模板正式重算，由服务端按本次提交的品种和值决定首次入库、跳过或覆盖 |
| `source_snapshot.complete`、`missing` | 来源完整标记和缺失原因列表。缺失活动量可省略或传 `null` |
| `source_snapshot.heat_sources` | 可选热力来源明细，`measured` 的 `amount` 为 GJ，`area` 的 `amount` 为 m² |

核算方只提交报表热力编码 `HEAT_REPORTED`。预测服务使用来源明细生成报表热力和内部可比热力 `HEAT`。面积热力需启用 `PREDICTION_MONTHLY_AREA_RULES_APPROVED`，并命中当月分公司专用 `GJ/m2` 规则。机辆电力的三个品种必须齐备且闭合。肃宁和原平只提交总电。

服务端按组织和月份串行处理。同版本重试返回原回执，原键对应不同请求体时返回 `409`。正式覆盖按“碳排放模版重新核算发生改变”记录审计。来源缺失或规则未通过时，整月暂存为 `pending_review`，保留缺项。来源待复核的月份在通过完整快照复核前不进入训练、关联分析和预测输入，历史的普通异常复核继续适用。

`GET /api/v1/prediction/ingest/monthly/capabilities` 用于核验接口和迁移已就绪。 `GET /api/v1/prediction/ingest/monthly/source/{org_id}/{period}` 用于查看版本、批次、待复核状态及缺失原因。回执状态包括 `completed`、`pending_review`、`skipped_existing`、`unchanged` 和 `superseded`。


| mark_breakpoint | 保留原值，标记结构断点            | —                |


- 同一 `var_id + effective_from` 为更新；其他生效期重叠返回 `409`；
- 历史已使用因子不物理覆盖，新增版本并重算受影响月份；
- 操作写 `prediction_audit_log`。

## 10. 集成时序

### 10.1 月度数据接入 → 复核 → 训练 → 预测

```
平台采集/核算
  │ POST /ingest/monthly
  ▼
预测模块：写 activity → 重算 emission → 异常检测
  │
  ├─ 无异常：completed
  └─ 有异常：pending_review
        │ 平台待办 → 人工复核
        │ POST /anomalies/{id}/review
        ▼
     completed
        │
        │ 每月/每季度按需
        ▼
POST /train (mode=auto) → job_id → GET /jobs/{job_id}
        │
        ▼
POST /forecast (horizon=12, scenario=BAU, write_db=true)
        │
        ▼
平台读 prediction_forecast / prediction_v_carbon_monthly
```

### 10.2 平台直接读库

平台可视化可绕过 API，直接查询：

```sql
SELECT * FROM prediction_v_carbon_monthly
WHERE org_id='JLG' AND period BETWEEN '2019-01-01' AND '2025-12-01'
ORDER BY period;

SELECT * FROM prediction_forecast
WHERE org_id='JLG' AND scenario='BAU'
ORDER BY period;
```

## 12. 错误示例

```json
{"code": 400, "message": "period 必须为 YYYY-MM 格式", "data": null, "trace_id": "..."}
{"code": 401, "message": "无效的 X-API-Key", "data": null, "trace_id": "..."}
{"code": 503, "message": "数据库不可用: ...", "data": null, "trace_id": "..."}
```

生产环境建议：

- 用平台网关统一鉴权，替换 `X-API-Key`；
- 对 `ingest/monthly` 增加请求体大小限制与字段级权限；
- 对 `train` 增加审批/配额，避免频繁全量训练。
