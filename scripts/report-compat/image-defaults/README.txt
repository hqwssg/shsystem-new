报告默认图片补齐 2026-10-22

范围
三家公司各提供封面Logo、组织机构图、机关所在地，共9个默认图片位置。
本次新增材料为：肃宁2024组织图、原平2024组织图、机辆2025组织图、机辆2025机关所在地照片。
图片均为原Word中提取的原始字节，不裁切、不重绘、不从其他公司借图。
机辆原图标注“现场图”，用户在本次会话中明确确认可作为机关所在地使用；保留原图注和确认记录。
组织图来自2024/2025年度历史材料，作为参考默认，填报时仍需核实是否符合本次报告期组织情况。
已有人工作业的有效默认图片保留，不覆盖；因此实际保留图可能与包内参考图不同。
不导入原平线路图或机辆平面图。

最简单的服务器用法
本包仅补图片，不含工作量、设备、周期或公式功能补丁，不需要重新部署Java/前端/Python。
前提是服务器已有此前报告模块、企业档案及report_file表；需MySQL8.x。
1. 上传init_report_images.sh到例如/opt/carbon-report-init/。
2. 确认数据库容器名：
     docker ps --format '{{.Names}} {{.Image}}'
3. 把下面的ruoyi-db替换为实际MySQL容器名，执行：
     bash /opt/carbon-report-init/init_report_images.sh --container ruoyi-db --database carbon_emissions --user root
4. 按提示输入数据库密码，密码不回显，不作为命令行参数。
5. 出现REPORT_IMAGES_INIT_OK和Completed后核对9行结果。
   INITIALIZED为本次补入；EXISTING_IMAGE_KEPT为保留已有图；EXTERNAL_REFERENCE_KEPT为保留外部存储引用，需另外检查引用可读。
6. 刷新报告“设备”页面或新建报告，检查三张配图。已有报告的自定义图优先保留，可使用“恢复默认”。

非Docker数据库可执行：
  bash init_report_images.sh --local --host 127.0.0.1 --port 3306 --database carbon_emissions --user root
服务器执行.sh不需要Python，不需要上传原始Word；所有图片二进制已内嵌。
init_report_images.sql为同一内容的SQL版本，仅供自行完成备份后使用；不要用mysql --force忽略错误。
check_images.sql为只读复核查询。

写入与保护
按公司全名和登记关系查找实际dept_id，不硬编码本地或线上ID，不迁移SH占位公司编码。
只向report_file补缺少或空的默认图片；原空默认记录转为archived_default并保留原ID，再插入新ID。
已有非空内容或外部存储引用不覆盖；哈希/大小异常、重复默认位置、错误报告绑定、公司身份冲突会整体停止。
不修改企业档案、设备、工作量、账号、权限、核算任务、核算结果或已有报告快照。
重复执行不会新增重复图片，也不会变更已有图片ID或时间。
执行用户需读取公司/档案表、读写report_file、临时表及创建/执行/删除辅助存储过程权限。
脚本事务回滚保护依赖report_file为InnoDB，脚本会先检查。

备份与回退
脚本写入前备份三家公司的现有默认图片，并打印备份与日志目录。
备份包含图片二进制，仅保留在服务器，不要将它混入发给他人的交付包。
初始化日志记录每个位置的动作和文件ID。回退时按该次日志、备份及当前引用核对，只处理该次新增/归档记录，避免覆盖后续人工图片。
不执行清空表、删除文件或全库恢复。源码材料可单独回退本组Git提交；源码回退不等于数据库图片回退。
